# 多群选择与合并名单验收

作者：ahui  
日期：2026-11-17

## 需求、现状与验收范围

此前目标群只有单选，排除群虽可多选，但不能取得多个目标群的合并结果。本次将目标选择、逐群获取、核验、统一筛选、SQLite保存、导出及固定邮件收件范围接成完整流程。界面只验收1920×1080，保留原蓝灰配色、深色主题和现有业务规则。

验收要求：跨搜索保留目标选择，可全选／取消／清空；重复QQ只计一人；目标与排除不能冲突；各来源完整性独立保留；任何读取错误或取消不发布半套结果；导出、写信、返回调整均绑定正确组合及名单版本。

## 实际行为

- 群名前复选框选择多个目标，每次最多200个；点击群名仍可快速查看该单群。“全选当前群”只作用于当前搜索结果，取消不影响隐藏选择，清空取消全部目标；超限保留原选择。目标勾选不跨启动记忆。
- 逐群串行获取、分别核验，再按QQ号合并去重。同一QQ的昵称／名片保留群号排序首个来源资料。摘要显示唯一人数，来源详情展示各群名、群号、人数和核验状态，不相加参考总数；任何部分／待核验来源都保留限制。
- 合并后统一处理排除群、可选好友、已发送和手动排除；好友列表每任务只读取一次。目标群全部从排除候选移除，后端也拒绝冲突。保存的筛选偏好仍按QQ账号隔离。
- SQLite按账号、来源和稳定群组合保存最新快照，勾选顺序不同仍读取同组结果。各真实来源群的元信息与组合快照在同一事务提交；原单群最新不被合并名单覆盖，也不向真实群目录插入虚构的组合群。来源成员归属保存在组合JSON中。
- 任一目标或排除群读取失败、取消、登录身份改变或任务超时，都保留上次已完成结果。每个目标／排除群按120秒任务预算，总上限30分钟；现有网络请求限制不变，无新增并发请求。
- Excel、CSV、TXT使用同一份去重最终名单。多群文件名标记“多群合并”，Excel附各来源核验元数据，CSV/TXT原字段不变。
- 写信页、替换范围和确认弹窗显示真实群来源；“调整群成员”恢复原组合和原快照。SQLite继续验证未选／已过滤成员，补充邮箱不能绕过。更换群或重新获取不自动替换邮件范围。
- 大于10000人的合并名单仍可查看和完整导出；发送状态按10000人串行分块、全部完成后应用，失败或漏项继续阻止收件范围交接。单次写信保留10000人上限，超限提示先勾选部分成员。多账号均分、共享历史／排除及两项默认间隔不变。

## 兼容、回滚与限制

SQLite schema保持5，旧快照缺少sourceGroups仍可读，无需迁移或清库。README、用法、技术方案和相关代码注释同步；UTF-8无BOM，技术方案与构建脚本保留CRLF，其他本次源文件保留LF。项目为Rust/TypeScript，已阅读Java手册，其Java语法、Javadoc和MyBatis专属条款不适用；通用注释、命名、校验与异常规范继续采用。

旧版本保留在`dist/remember-options/QqGroupExporter.exe`，SHA256为`F4470E9F61DE767EBD7B7CB6E4E142A8C4BEE6297481E2C0E631738EFC5C51DA`。回滚先退出当前进程再启动旧EXE；旧版忽略新增来源JSON且无多群入口，不主动删除组合数据。需要完整恢复升级前组合状态时，退出程序并恢复事先备份的完整应用数据目录；不要删除SQLite或只拷贝单张表。源码基线、补丁、变更清单另存于`artifacts/multi-group-baseline/`、`multi-group-source.patch`和`multi-group-changes.json`，未覆盖用户的原有工作。

本次不连接真实QQ、不读取用户数据库、不发送真实SMTP邮件；实际账号可用性、服务端权限、读取完整性、额度和投递接受仍需真实环境验证。合并快照规模随所选群成员总数增加，串行获取可取消，任务超过30分钟应分组获取。群名／名片以获取时状态为准，不能证明所有群在同一时刻的成员全量。
