# 快捷发送与手动排除交付记录

作者：ahui

日期：2026-11-06

## 范围与实现

本轮在既有 React / Tauri / Rust / SQLite 项目上增量实现，保留原有模板、正文图片、SMTP 设置、好友排除、历史核实、失败继续、300 秒间隔和日志；不关闭用户运行中的旧程序，不操作用户数据库，不发送真实邮件。

- 写邮件增加“快捷发送 / 群成员发送”。快捷输入完整邮箱，不依赖 QQ 会话；两种模式独立保存输入地址，共用内容和发件设置。群交接明确切到群模式，普通名单更新不切换模式。
- 成员表提供单条“排除”和“排除所选 N 人”，操作前确认全局影响，行内操作不误勾选。独立“手动排除”工作区支持批量添加 QQ 号/邮箱、备注、搜索、分页、整行/键盘选择与确认移除。
- 全局排除在所有群、提取账号、补充邮箱和快捷模式生效，不冒充已发送；移除只恢复原本合格成员，不解除群/好友/历史限制，不自动增选当前邮件收件人。
- 原始名单不改写。相同快照 ID 和时间派生当前视图，人数、已过滤原因、Excel、成员选择与邮件联动；旧邮件按自己的 ID 更新，不切换到最新群。规则变化撤销旧确认，导出绑定版本，实际投递事务再次校验。
- 保存失败保留输入，已提交但派生失败明确提示并补读；名单读取失败提供“重新加载名单”，不需重新登录或读取 QQ。写操作具备同步门闩，任务运行、等待或停止中只读。
- 全部候选被过滤时前端不打开发送确认，后台也在保存设置、消费计划或创建任务前拒绝空任务；原有 SMTP 失败和待核实语义不变。
- 视觉复查统一手动排除页标题与刷新布局、紧凑选择/操作列；移除排除后按实际交集显示全选或部分选择，避免候选恢复但仍冒充已全选。Vite 排除发布目录监听，避免 Windows 写入 EXE 触发开发测试的文件占用错误。

主要文件：`frontend/App.tsx`、`components/MailComposer.tsx`、`components/ManualExclusionsPage.tsx`、`components/MemberMailActions.tsx`、`components/GroupAudiencePanel.tsx`、前端类型/样式/桥接/回归；核心 `manual_exclusions.rs`、`database.rs`、`models.rs`、`verify.rs`、`export.rs`；宿主 `exclusion_commands.rs`、`commands.rs`、`state.rs`、`mail_commands.rs`、`recipient_commands.rs`、命令注册与诊断白名单。`templates.rs` 只同步数据库版本测试断言。

## 数据兼容与回退

当前 SQLite schema 为 3。兼容 0/1/2，既有模板升级后新增 `manual_exclusions`、`manual_exclusion_state`，表和版本同事务提交，迁移失败整体回滚；不清空名单、历史、模板、设置。旧快照 JSON 缺少 `manualFilteredCount`、`exclusionRevision` 时按零读取，再应用当前规则。高于 3 的数据库拒绝打开。

升级前请先退出旧程序，备份整个 `%LOCALAPPDATA%/com.ahui.qq-group-exporter` 数据目录（包含可能存在的 WAL 等文件）。回退旧 EXE 时须保留新数据另存，再恢复升级前完整备份；旧版拒绝 schema 3，禁止手改 `user_version`。新排除记录不会出现在旧备份中。

每次添加最多 10000 个非空项、512 KiB，备注最多 500 字且不能包含控制字符；换行、中英文逗号/分号可分隔。重复项不改原备注和时间，合法项可保存，非法项明确计数并保留输入。批量移除任一 ID 失效就整批拒绝。邮箱仅域名忽略大小写，其他品牌和别名不推断 QQ 身份。

## 已知限制

本轮未使用真实 QQ 登录、好友或成员数据，也未执行 SMTP 真实投递；不能宣称真实送达已验证。浏览器检查不能替代 Windows 原生窗口/标题栏、系统剪贴板、系统保存框和无开发环境机器的实机验收。旧名单超过最近 20 份保留范围后不能恢复，需重新获取。外部邮箱、QQ 邮箱别名与数字 QQ 的对应关系未知，必须分别维护需要排除的完整地址。

切换过的群保留在界面内存缓存中时，已经被数据库淘汰的旧版本可能持续触发“部分名单更新失败”；当前仍有效的版本独立恢复且可用，不会因此一同被阻止。绑定了淘汰版本的草稿需重新获取并确认替换范围；本轮没有增加历史保留数量或重建已淘汰记录。

沿用现有依赖，没有新增第三方库或常驻服务；第三方声明无需新增条目。中文、注释与使用说明同步。项目使用 Rust/TypeScript，Java 手册中的语言专属条款不适用，通用输入校验、注释、异常、格式与凭据保护要求继续采用。
