## 成员管线与存储

任务冻结当前账号、目标群、排除群和筛选条件。逐个目标读取并核验原始人数，按QQ号取并集，最后统一群重合、好友、已发送及手动排除。任一网络失败、取消或账号变化不发布半套结果；保存与取消共用门闩，迟到响应通过任务／代次校验丢弃。

`Snapshot.sourceGroups`可缺省，旧单群为空；多群保留各来源原始QQ归属、参考人数与核验状态。内部组合键由排序去重群号构成，只用于存储和比较，不作为QQ网络目标或群号显示。同一人多个来源只占一名成员；任一来源部分／待核验时不会被其他来源重合掩盖。

SQLite schema为5。群目录与最新快照按来源、QQ账号和单群／组合隔离；最近20份历史之外，各单群或组合仍各留一份最新结果。多群保存同时更新真实群目录，原单群最新不被合并覆盖。手动排除实时叠加当前快照；恢复过滤成员生成有原原因记录的新版本，不改原获取时间或删除共享规则。

导出使用明确`snapshotId`，不从全局最近结果猜测，不受屏幕搜索缩小。Excel以文本保存QQ和昵称，附核验与过滤元数据；CSV为UTF-8 BOM、CRLF，危险公式前缀加单引号；TXT为UTF-8无BOM、CRLF。写入使用原子替换，失败保留已有文件。

## 邮件与凭据

预检从SQLite重读群范围，合并完整邮箱并去重，应用共享手动排除及可选历史，生成5分钟有效的冻结计划。确认绑定名单、参数和账号修订；历史／规则变化须重新准备，不能采信前端群名、人数或自行构造的成员资格。

随机均分保证各已选账号人数相差最多1，不重新打乱已确认计划；每账号按逐人／密送拆批，调度每轮最多一批，优先就绪账号。同账号结束到下批之间使用单调冷却，账号切换独立等待，最终取较晚期限而非重复相加；末批后不等待。停止阻止后续批次，不撤回已进入SMTP的当前操作；不确定结果登记待核实并阻止再次投递。

SMTP授权码在Windows本机保护机制下独立加密，绑定账号ID与连接／发件身份；SQLite只保存公开配置。图片与附件使用受控内存资源，正文预览隔离脚本和外部资源，内嵌图片由CID进入邮件；模板独立保存正文及资源副本。完整限制见[使用说明](使用说明.md)。

## 更新与发布

关于页沿用软件信息、版本更新、项目与反馈、本版功能的纵向卡片布局，展示当前版本、Windows x64 免安装模式、GPL-3.0-only 与作者；更新操作固定在底部。项目链接包括 GitHub 项目、发布记录与问题反馈。Vite 将项目协议、第三方说明及许可合订本生成为 `licenses/` 下的三个文本资源，随前端资源嵌入 EXE；许可原文和对应源码保留在仓库及同版本 Tag。

更新只请求`ahuiyuchuan/batch-send-email`的公开GitHub正式发布信息，读取与业务状态／锁分离；启动和每小时静默检查，手动入口给出真实状态与重试。只有语义版本更新才提示新版，不能以网络错误或“没有正式发布”冒充最新版；外链由后端白名单校验后交给系统浏览器，不自动下载、执行或替换EXE。

公开名称为`batch-send-email`，保留Tauri标识及历史本机偏好兼容键，避免更名后变成空白数据目录。发布版本、Tag、Release和资产规则见[贡献指南](../CONTRIBUTING.md)。更新后完全退出旧进程再启动；源码回退需前后端一起，涉及数据库变化时先恢复升级前完整备份，不能只降低schema编号。

## 诊断与验证

日志在`%LOCALAPPDATA%/com.ahui.qq-group-exporter/logs`。当前文件`app.jsonl`，另保留4份循环备份，每份最大5MiB；查看仅读取当前尾部256KiB中最多200条完整记录。不得记录正文、主题、完整邮箱、凭据、Cookie、二维码或原始响应；前端错误仅记录白名单类型与包行列。日志写入故障不阻断业务，也不能用日志表示收件箱已送达。

只在虚构IPC与本机模拟服务下执行自动回归，不读正式数据库或发真实邮件。当前检查范围与限制见 [VALIDATION](../VALIDATION.md)，历史验收文件记录当时行为和产物，不应误当作当前发布命令。核心技术细节见 [QQ群成员导出方案](QQ群成员导出方案.md)。
