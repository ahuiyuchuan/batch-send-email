# 成员过滤恢复与错误处理验收

作者：ahui

日期：2026-11-09

## 问题、根因与本次范围

群发送补充栏会正确阻止源群中已过滤或未勾选的 QQ 邮箱，但旧页面只显示总数，无法定位和移除具体输入；“已过滤”表没有逐人解除入口。取消整个排除群后重新获取会影响其他成员，不能满足单独保留一人的需求。

本次补齐成员、补充邮箱、手动排除和发送记录之间的处理路径；沿用现有界面与存储。用户补充要求后，最终布局仅在 **1920×1080** 验证，不再测试其他尺寸。此前完整回归已运行的其他尺寸结果属于过程记录。

## 业务行为与兼容性

1. 从补充栏点击“定位成员”，回到邮件原群、原版本和对应标签，并搜索号码；不会猜测最新名单替换旧邮件。
2. “恢复到名单”只对本保存版本生效。已获取成员资料和原获取时间不变，审计另记本地调整时间；重新获取按原选项重新过滤，不保留本次例外。
3. 同时命中群重合与好友的成员可作为本版本明确例外，确认中说明；未知好友关系仍拒绝，不伪造非好友状态。
4. 恢复不删除全局手动排除、已发送记录或待核实状态。手动排除继续遮蔽恢复成员，发送前“跳过已发送”与未决阻止仍独立生效。
5. 原邮件范围不自动加入恢复成员；用户勾选后点击“给已选 N 人写信”并确认替换。主题、正文、附件、图片与补充输入保留。
6. SQLite schema 仍为5，仅在名单 JSON 增加可缺省的 `restoration`。无需改表或清空原数据。获取及恢复版本共同保留最近20次，各群最新结果额外保留。新旧版本可按保留策略读取，不承诺永久保留完整历史。
7. 回退到本次前的 schema5 EXE 前，优先重新获取调整过的群以生成无例外结果；旧程序不理解好友例外，可能拒绝调整名单。不要为回退而覆盖当前发送记录。schema4及更早程序有原有版本不兼容约束。
