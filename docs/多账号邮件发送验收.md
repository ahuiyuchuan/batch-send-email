# 多账号邮件发送验收

作者：ahui

日期：2026-11-09

本文记录此前多账号发布包的行为和检查结果。后续已将账号间统一等待改为按轮次、同账号间隔，当前行为与新版交付见[同账号间隔与轮次发送验收](同账号间隔与轮次发送验收.md)。

## 需求与实现

本轮接续登录恢复、选择便利性、模板交换和群数据 SQLite 保存。原写信页只支持一个 SMTP 发件账号；现在可管理最多 20 个，各账号独立保存凭据，发送时共用本机已发送记录、待核实投递与手动排除名单。

按用户最终要求，界面默认随机均分，不提供分配方式选项。先对候选收件人去重、应用手动排除和“跳过已发送”规则，并阻止未核实投递，再分配实际待发人数。N 人、M 个选中账号，每账号为 floor(N/M) 或 ceil(N/M) 人，差最多 1，每个地址只分配一次。5 账号分 8 人为随机 3 个账号各 2 人、其余各 1 人；10 人各 2 人；2 人随机两个账号各 1 人，其余 0 人。本次分到 0 人的账号明确展示“不发送”，不要求为该任务提供授权码。

随机地址顺序和账号顺序仅在预检生成一次，确认页列出账号邮箱、人数、预计封数及合计。确认发送使用同一份固定计划；账号、凭据、选择、模式、每封人数或全局排除/历史变化使旧确认失效，5 分钟过期需重新预检。客户端账号数组顺序不能替代已确认的随机顺序。

“发件设置”提供添加、编辑、删除确认、上下移动、独立凭据状态和清除；写信页默认全选，新增账号也默认选中，可全选、取消全选或逐一选择。所有账号取消选择时禁止发送。账号修改须先保存；关闭设置或切换账号保留当前窗口的未保存输入，删除另一账号后也会恢复对应草稿，可明确“放弃未保存修改”。普通失败保留输入供重试；目录已提交但旧密文清理失败会报告部分完成并重读目录，读取失败时锁发送并提供重试，避免重复猜测或误用旧配置。

保留既有密送分批默认值：每封 20 人、间隔 300 秒，也可逐人发送。分批在每账号自己的名单内进行，总封数为各账号封数之和，不能把人数当封数。所有实际参与账号先完成凭据与邮件构造校验，任一个不可用则零投递。队列在全部账号之间串行，批次共用原间隔；失败按原停止/继续开关处理，不自动换账号重投或重新分配，停止不强行把正在进行的 SMTP 交互认定为失败或成功。SMTP 接受仍不等于进入收件箱。

## 协议、持久化与回退

- `mail_accounts()` 返回 `{revision, accounts}`，只包含公开 SMTP 字段和 passwordSaved/passwordStatus/passwordMessage；`mail_account_save({input:{id?,name,settings}})`、`mail_account_remove({id})`、`mail_accounts_reorder({ids})`、`mail_account_clear_password({id})` 返回完整目录。密码仅作为保存输入，响应不回显。
- 新预检传 accountIds/accountRevision/sendMode/batchSize/allocationMode，其中当前页面固定 allocationMode="random"。计划返回 accountAssignments 和 totalMessageCount；start draft 必须带同一 accountIds/accountRevision/allocationMode 及固定计划 ID。缺省 ordered 仅兼容旧 IPC，不与 random 计划混用；显式空账号集合不能退回默认账号。旧 get/save/clear settings IPC 映射目录首项，旧临时密码发送协议仍保留，新页面须先保存账号。
- SQLite 继续 schema 4，不新增表；`settings.smtp_sender_accounts_v1` 存 v1 公开目录、凭据引用和 revision。首次读旧 `smtp_public` 时迁入 `legacy-default`，继续引用旧 `smtp-credential.bin`，不会因迁入读取真实明文或改写密文。即使删除全部账号，也保留空目录标记防止旧配置复活。
- 新凭据文件在固定应用数据目录 `smtp-accounts/{账号ID}-{随机版本}.bin`，用 Windows 当前用户 DPAPI 加密，绑定账号 ID 及 SMTP 身份。先写新密文，数据库事务再提交引用与 revision；提交失败清理新文件并保留旧引用。成功后清理无用旧密文，失败明确报告实际部分完成，不声称文件和 SQLite 属于同一事务。显式清除/删除也清理该账号对应密文，不能假定旧 legacy 文件会永远保留。
- 数据目录仍为 `%LOCALAPPDATA%/com.ahui.qq-group-exporter`，不随 EXE 路径变化。升级或回退前正常退出程序，备份整个目录（含可能存在的 WAL、旧凭据及 smtp-accounts 子目录）。多账号之前的 schema 4 程序不能管理新目录，旧 smtp_public 不保证同步多账号变更；要恢复原行为须恢复升级前完整备份，不能只删新设置或降低 user_version。更早 schema 0/1/2/3 升至 4 继续按群保存版本的事务迁移和完整备份规则处理。
- 当前账号选择、随机确认计划及未保存草稿仅在当前窗口内存，模板导入导出不包含 SMTP 设置或凭据，不能用于搬迁密文；DPAPI 文件不能迁给另一 Windows 用户或电脑。

## 发布与限制

新版为 `dist/multi-account/QqGroupExporter.exe`，根目录 `dist/QqGroupExporter.exe` 是同一副本，18,136,064 字节。SHA256：`F2555DDC811E6D38F308C6CBCCE56E1C92C5FE5D8DF3A6C7570BDF40712B8570`。

使用前先正常停止任务并退出旧版，再打开新 EXE；程序为单实例，旧版未退出时再次打开可能只回到旧窗口。没有关闭用户正在运行的旧进程，也没有读取真实用户数据库或凭据。

未执行真实 QQ 登录/群获取、多账号真实 SMTP 接受/退信/额度、原生文件框人工操作、无开发环境或缺 WebView2 的 Windows 实测。隔离回归验证本地业务和状态边界，不能保证真实 QQ 会话持续有效、服务商额度或邮件进入收件箱。标题正文及随机插字不能保证避开垃圾邮件判定，建议见使用说明；均分功能不改变收件人许可、服务商规则和拒收名单约束。
