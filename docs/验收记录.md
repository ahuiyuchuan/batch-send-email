## 本轮：批间倒计时、默认 300 秒与日志查看

用户最终指定默认每批间隔为 300 秒（5 分钟），覆盖先前的 120 秒提议。仅调整新任务预设及等待反馈，显式填写的 1—3600 整秒仍按输入生效；不改 SMTP 超时、失败分类、unknown／待核实、失败继续、发送记录及邮件资源逻辑。保留好友列表、日志、模板和批量核实等既有改动。

- `src-tauri/src/mail_commands.rs`：新增阶段、下一批 UTC Unix 毫秒截止时间及进程内跨任务递增版本。实际等待使用 Tokio 单调时钟，页面时钟不触发投递。下一批发送、取消及终态清理截止时间，末批没有多余等待；`batch_wait_started` 仅记录一次任务/下一批/间隔/截止时间，不逐秒写日志。终态提交与清理旧取消令牌和新任务建立使用同一门闩，并核对任务身份，防止旧执行体清除新任务状态。
- `frontend/components/MailComposer.tsx`、`mail-types.ts`、`mail.css`：默认 300；区分投递、等待、停止；等待显示下一批和 mm:ss。每秒重算截止时间，回到前台立即校准，归零只显示准备下一批。旧版、重复及迟到事件不能倒退阶段；倒计时独立更新，不刷新历史、不重新筛选名单、不逐秒读宿主或重复播报。保持既有任务期间查看其他页面和打开日志能力。
- `frontend/tests/ui-check.mjs` 与宿主测试：覆盖默认值、整秒边界、同计数和跨任务乱序、切阶段、刷新/重载恢复、系统时间跳变、停止与终态；宿主覆盖发布并发、旧执行体身份和序列化。
- `crates/member-core/src/mail.rs`：仅 SMTP 550 且服务端原因明确为 Too many attempts 时，使用固定中文“发送过于频繁，请稍后再试”；其他 550、认证、网络错误保留原提示。错误码及投递未确认规则不变，详细脱敏响应仍写日志；未成功项保留安全原因，等待和后续批次不会抹去。
- `src-tauri/src/diagnostic_commands.rs`、`main.rs`、`frontend/components/LogViewerDialog.tsx`、`App.tsx`、`styles.css`、`bridge.ts`：导航增加文字“查看日志”，发送期间可打开只读窗口、刷新或重试、打开原目录查看全部文件。读取固定 app.jsonl 尾部最多 256 KiB、最近 200 条完整 JSON 对象，不接受路径；中文边界、损坏及正在写入的残行跳过，缺失/空文件可正常空态。读取不自写诊断、不改变日志、邮件或任务，失败保留上次内容。
- README、使用说明、方案同步默认、交互和边界；无新依赖，第三方声明无需增加条目。SQLite schema 仍为 2，无迁移、无数据库清空；退出后换回上一 EXE 即可回退本轮改动，已有模板 schema 回退规则继续适用。

查看正在运行的旧版日志，QQ SMTP 在北京时间 18:44、18:48、18:53 等批次返回 `550 Too many attempts. Unable to send. Try again later`。前五批共 100 位收件人的提交返回 250；当前任务第三批在 18:58:08 返回 250，说明失败继续设置下确实仍执行后续批次。该证据仅说明服务端以尝试过于频繁拒绝了相应提交，以及后续一次提交被接受，不能推出固定额度、冷却时长或最终进入收件箱。默认 300 秒也不保证不再触发限制。

后续只读日志显示，北京时间 19:22:01 的最新一次任务正常结束：服务器接受 20、失败 0、跳过 202、未尝试 0。这些是用户运行中记录的观察，不是开发测试主动触发的投递。

只读取脱敏应用日志，没有主动投递真实邮件、读取/解密授权码、改动用户投递记录或关闭其旧程序；上述日志观察不能替代新版 SMTP 端到端验收。新版须在旧任务结束或由用户停止并退出旧程序后启动，无法给运行中的旧 EXE 动态补上倒计时。

## 行为与边界

- 日志固定在 `%LOCALAPPDATA%/com.ahui.qq-group-exporter/logs`，当前为`app.jsonl`，四个循环备份槽为`app.1.jsonl`至`app.4.jsonl`；共五份、每份最多5MiB，UTF-8无BOM且每行一个JSON对象。备份编号不表示时间顺序，按timestamp/修改时间查找。
- 常规日志条目含带时区的时间、进程/会话标识、级别、模块、事件和受限字段。SMTP保留服务商返回的错误状态与脱敏摘要；不启用wire trace，不记录AUTH命令、密码/授权码、Cookie、二维码、主题、正文、完整邮箱/QQ号或文件路径。
- 已知SMTP敏感身份额外按精确值脱敏，额外明文副本由Zeroizing擦除。泛化脱敏与字段/条目/嵌套/单条长度限制作为第二道边界。日志不是任意邮件内容匿名化工具，调用方仍禁止传入邮件内容。
- 当前文件轮转使用原子替换最旧循环槽，查看器占用导致失败时不先删除旧历史；半行中断/部分写入后重开修复尾部再写，保留完整行。日志I/O失败不改变邮件/保存结果，GUI提示且后续事件最多每10秒重试初始化；已有写入器失败可在后续事件重试。
- 页面只上报固定命令名、状态、耗时和安全错误码，get/poll成功每命令每分钟最多采样一次，失败保留。JS错误仅保留白名单类型、包文件名及正整数行列，不发送自由消息/URL查询/堆栈；日志命令自身不递归上报。
- 模板与数据库兼容保持原样；schema仍2。回退本轮可退出新版后换回上一包；日志文件独立，不需清空或降级数据库，现有schema1→2回退规则仍见使用说明。
- 必须启动新版后才开始产生新日志；旧版已丢弃的SMTP错误不能还原。本次好友接入不改变SMTP诊断与投递规则，现有实际发送问题仍需新版记录的错误定位。
