# 确认结束时间与偏好记忆验收

作者：ahui；日期：2026-11-16。

## 目标与根因

确认弹窗原来只显示分封和间隔，结束时间仅在任务启动后存在。发送选项只有组件内状态，重启丢失；名单筛选还会在切群或恢复快照时被旧快照/默认值重置。目标是在保持现有名单保护、随机均分、账号冷却和发送账本规则的前提下，补齐确认前动态时间及操作偏好。

## 修改与边界

- `frontend/components/ConfirmationEstimate.tsx`：仅在确认弹窗打开时每秒串行读取一次只读估算，回到前台立即校准；关闭、返回修改或确认后销毁计时，迟到响应丢弃。显示本机完整日期时间，错误自动重试且不连续弹通知。
- `src-tauri/src/recipient_commands.rs`、`mail_commands.rs`、`main.rs`：新命令 `estimate_prepared_mail_completion(input)` 接受计划ID、同账号秒数和切换秒数，返回可空UTC毫秒。人数、账号顺序和封数从冻结计划取，使用实发调度器的纯模拟入口，考虑已有单调冷却或SQLite中的重启冷却；不重新随机、不取凭据、不联网、不消费计划、不写数据库。每封10秒为初始估计，实际运行仍随样本更新。估算非送达保证；异常重启pending保守按原间隔估算，实际恢复仍在发送入口提交。
- `frontend/lib/preferences.ts`、`MailComposer.tsx`：v1白名单偏好记住六项发送参数和展开状态。数字逐项校验，编辑中的无效值保留上次合法值，明确0才关闭切换间隔。首次默认不变；发送确认五分钟到期自动撤回并提示重新确认。
- `frontend/App.tsx`：名单筛选按 `source:qqNumber` 保存三个筛选项和展开状态；同账号切群沿用，目标群和当前群目录以外的ID不提交。仅明确操作保存，不因被动刷新或快照恢复删选项；不会改变已有获取快照或邮件来源。
- `frontend/tests`、`package.json`、`scripts/build.ps1`：新增偏好单测及1920×1080业务回归，纳入现有全回归和默认构建。README、使用说明和架构文档同步。

偏好使用现有WebView2用户数据目录的localStorage，键为 `qq-group-exporter-mail-options-v1` 和按账号编码的 `qq-group-exporter-list-filter-v1:`。不保存主题、正文、收件地址、账号凭据或Cookie。坏JSON、未知版本及无效字段按原默认逐项恢复；存储被拒绝时显示一次失败提示但当前操作继续。账号公开标识及群标识仅用于本地偏好隔离，不进入诊断日志。

无SQLite schema、发送协议或既有命令参数迁移。新估算命令是增量接口，旧调用方不受影响。回滚旧EXE会忽略新localStorage键；可保留或删除这两个前缀对应的偏好，不删除业务数据库、冷却或凭据。源码修改前副本与哈希在 `artifacts/remember-options-baseline`；工程源码仍是原有未跟踪状态，不用git diff冒充完整差异。
