# 发送选项表单对齐修复验收

作者：ahui  
日期：2026-11-12

## 现象、根因与遗漏

用户提供的1920×1080截图中，写信页左下角“发送选项”的下拉框与数字框未对齐。原版实际渲染复现：下拉框左边缘228px，三个数字框207px，相差21px；下拉框高度35px，数字框33px。修复前新增的几何回归在原布局上真实失败，保存截图 `artifacts/frontend/send-options-before.png`。

根因为各行使用flex加margin-left:auto，数字框后还有“人/秒”，下拉框没有尾随单位；自动空白按剩余内容分别计算，无法保证共用列线。select与number的原生行高和内边距也没有统一。此前验收检查了展开后的默认值和操作，但截图前就收起，没有验证展开时的组件几何；本次补上该缺口，不能把此前业务检查通过等同于视觉没有问题。

检查发现的相邻问题：发送模式按钮同时带primary与aria-pressed，通用主按钮hover覆盖分段控件底色，文字却仍使用分段颜色，深色主题悬停时不清楚。此次一并修复。

## 改动与影响

- `frontend/components/MailComposer.tsx`：四个参数字段使用显式mail-option-field，标签及三处单位使用span；发送模式仅用aria-pressed标记选中，移除primary样式类。保留所有字段名称、数值、onChange、禁用条件及输入校验。
- `frontend/workbench.css`：参数统一为“自适应标签/112px控件/1em单位”三列，select没有单位也保留末列；控件使用现有36px高度令牌，标签和单位垂直居中，数字靠右、选项文字靠左。复选框取消原生外边距。分段选中配色优先于通用hover。
- `frontend/tests/ui-check.mjs`：assertSendOptionsAligned读取真实DOM矩形，核对所有控件左边缘、宽高、标签左边缘、单位列和文字垂直位置（允许1px列线/尺寸、2px文字中心偏差）；截图覆盖浅/深色×群/快捷×密送/逐人8种组合和两种主题的任务运行禁用状态，另外检查选中按钮悬停颜色。
- README、使用说明、架构方案及本文同步说明修复和发布路径；代码注释说明三列预留单位和分段样式隔离的原因。

仅修改前端布局/展示和回归脚本，无数据库、IPC、配置默认值或后台变更。发送行为、随机均分、900秒/60秒默认间隔、共享历史/排除、冷却、等待与取消规则不变。MailComposer的70个事件处理属性经TypeScript AST比较保持一致；无数据迁移。

此项目使用React/TypeScript/CSS/Rust，按现有格式及通用注释规范执行，Java/MyBatis专属条款不适用。沿用UTF-8无BOM，前端及使用文档LF，架构方案CRLF。没有新增依赖或修改生成源码、图标素材。
