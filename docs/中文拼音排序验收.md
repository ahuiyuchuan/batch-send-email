# 中文拼音排序验收

作者：ahui

日期：2026-11-11

## 规则与影响范围

此前中文与符号统一按 Unicode 码点排序，中文名称无法按拼音查找。本次修改统一展示比较器，顺序为数字 → 英文 → 中文拼音 → 其他字符，空名称置后。例如 `2群 → 10群 → a群 → B群 → 阿群 → 波群 → 李群 → 张群 → 中群 → !群`。

首个汉字按拼音首字母 A–Z，同首字母继续比较拼音；相同汉字再比较后续字符。英文忽略大小写，连续数字仍用有效位数和字符串比较，不转浮点数；同音汉字以码点定序，同名项目按稳定业务 ID 排列。其他字符保持码点顺序，首尾空白仅在比较时忽略。

采用现有 Node/Edge/WebView2 内置的 `Intl.Collator`，明确指定 `zh-Hans-CN-u-co-pinyin`，不依赖系统显示语言，无新依赖、词库文件、联网查询或本机数据读取。比较器实例复用；多音字采用运行时默认单字读音，不按词义判断。未收录拼音的生僻字沿用运行时中文校对顺序，ICU 版本更新可能影响个别生僻字，不保证任意多音词的语境读音。

群聊、排除群、模板库及导入预览、成员、过滤成员、群收件人、发送记录和手动排除继续使用同一比较器。纯 QQ 号及邮箱的现有排序不变；数字/英文前缀相同后遇到中文也按新规则比较。发件账号的手动顺序、日志时间顺序不变。

仍只创建展示数组，完整排序后搜索、分页。不会改写原始快照、导出顺序、冻结的收件范围、SMTP 随机均分或发送冷却；共享历史、排除与 QQ 扫码行为保持。SQLite schema 5、宿主接口与配置不变，无迁移。时间复杂度仍为 O(n log n) 次比较，额外 O(n) 展示引用，字符串比较另计字段长度；源集合未变化时复用现有缓存。
