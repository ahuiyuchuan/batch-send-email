# 前端简化重构验收

作者：ahui  
日期：2026-11-12

## 目标与约束

按用户要求重构整个前端展示与交互层，保留已有业务功能，只验收1920×1080。使用React/TypeScript现有技术栈与规范，不引入新的UI框架、状态库、字体或运行依赖。Java手册中的命名、注释、异常处理与验证原则适用；Java/MyBatis专属语法与框架条款不适用本项目。

界面以内容优先、字段分组、清楚的当前选择和可恢复操作为原则；保留应用自己的名称、图标、系统字体与Windows平台控件。

## 分析与实现

原界面的主要问题是全局头部和导航分两行、常驻教程和重复标签过多、各页标题结构分散、账号列表与配置纵向堆叠、长写信页必须滚到底部才能发送。重构后四个工作区使用统一层级、中性语义颜色、系统字体和原有Lucide图标；蓝色用于主操作和选择。

| 决定 | UX | DX | AX |
| --- | --- | --- | --- |
| 单行AppToolbar | 导航、身份、扫码和应用动作集中；头部68px | 全局展示与业务编排分开，事件门禁沿用App | 单一nav、稳定按钮名称、aria-current |
| 四页WorkspaceHeader | 标题、实际计数和操作位置一致 | 统一标题结构，没有复制业务状态 | headingId与页面名称稳定，顺序与视觉一致 |
| 12类DialogLayout | 标题及操作始终可见，仅主体滚动 | Fragment保持原生dialog直接子节点，统一滚动契约 | 显式dialog-body/dialog-footer，不靠子节点序号寻找操作区 |
| 写信页分层 | 图片/附件集中，发送参数默认收起，发送/停止固定在可视底部 | 同一编辑器与参数状态，无第二套草稿或设置 | 原生details支持键盘，字段名称/范围/校验保留 |
| 账号列表与表单分栏 | 左选账号，右侧编辑，保存取消固定 | 复用原CRUD、异步门闩和凭据判断 | 账号选择、字段、删除确认仍有独立名称 |
| 精简常驻文字 | 去掉标语、教程与重复的可选/导出标签；空输入不展示无效全选动作 | 说明集中到使用文档和控件title | 名称表达动作，动态错误与边界状态仍就地可读 |
| 共用语义颜色及反馈 | 深浅色一致，通知避开全局工具栏及底部发送栏 | 延续已有主题与单一Sonner实例 | 清晰焦点、状态语义和图标名称 |

快速回归发现新的单行工具栏会被原右上通知遮挡，导致外观按钮无法点击；已把通知移至右下，保留80px底部距离及原生dialog的portal机制。不是通过强制点击或关闭提示绕过此问题。

## 修改范围

- 新增 `frontend/components/AppToolbar.tsx`、`WorkspaceHeader.tsx`、`DialogLayout.tsx`，包含作者及职责/约束注释。
- 修改 `frontend/App.tsx`、`styles.css`、`mail.css`：全局工具栏、成员布局、主题令牌、列表和各工作区排版。
- 修改 MailComposer、SenderAccountsDialog、MailTemplateDialog、TemplateImportDialog、HistoryPage、ManualExclusionsPage、FilterOptions、GroupAudiencePanel、AudienceReplaceDialog、LogViewerDialog、FeedbackHost：结构统一、低频参数展开、冗余文字精简、固定操作区与通知位置。
- 更新 `frontend/tests/ui-check.mjs`：新增apple-clean入口，完整执行该入口时所有视口均固定为1920×1080，覆盖原业务交互和新布局，包含四页及关键弹窗深浅色截图。历史专项入口保留原尺寸覆盖。
- 同步README、使用说明、架构文档及本文。原有作者信息保留，未添加虚假版本/工单。

## 业务与兼容性

SQLite schema5、IPC结构、Rust服务、依赖和锁文件均未改动。现有群/成员缓存、过滤与恢复、导出、全选/跨页选择、手动排除、发送记录及账号归属、模板保存/导入/导出、多账号默认随机均分、共享历史和排除名单继续沿用。扫码取消/失败保留当前账号、最新扫码替换账号、退出后重新登录等规则不变。

同账号900秒及账号切换60秒默认值、冷却持久化、等待取较晚期限、取消优先、一次跳过当前等待和旧响应版本门禁不变。发送参数仅移到“发送选项”，范围和校验不变。收起设置不会清空已填值，页面切换不会卸载草稿。移除的教程规则在使用说明中保留，名单异常、凭据不可用、待核实、未保存修改及危险确认继续显示。

无需迁移，不删除或重写已有数据。关闭新版后可运行 `dist/interaction-polish/QqGroupExporter.exe` 回退，使用相同数据目录；不要清空数据库或SMTP凭据。源码回退依据 `artifacts/apple-clean-baseline/manifest.json` 及其镜像，新增三个公共组件需配套移除；不可使用git reset覆盖其他未提交文件。

发布：`dist/apple-clean/QqGroupExporter.exe`，根目录 `dist/QqGroupExporter.exe` 为同步副本。使用 `scripts/build.ps1 -SkipTests -OutputDirectory dist/apple-clean` 打包；SkipTests仅跳过已单独完成的同版检查，不跳过生产前端和原生构建。EXE大小、SHA256及图标检查结果见文末发布校验。

本次没有真实QQ/SMTP联调、实际投递、原生Windows标题栏外观验证或原生应用完整实机操作；浏览器夹具不证明这些外部服务结果。最终apple-clean验收限定1920×1080。生产构建仍有大于500kB的主JS分块提示（约746kB，gzip约274kB），没有隐藏该提示；本轮未为视觉重构改变既有同步排序依赖和加载生命周期。
