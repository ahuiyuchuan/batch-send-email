# batch-send-email 使用说明

作者：ahui

## 开始之前

本工具适用于 Windows x64，界面使用系统 WebView2 Runtime。发布的 EXE 可以直接启动，无需安装 Node.js、Rust 或独立浏览器。若系统缺少 WebView2 Runtime，需要先安装微软提供的运行时。

正式发布通过 [GitHub Release](https://github.com/ahuiyuchuan/batch-send-email/releases) 提供单个带版本的 Windows x64 EXE，首版为 `Batch-Send-Email-v1.0.0-Windows-x64.exe`。从源码构建的原始产物为 `target/release/batch-send-email.exe`，构建脚本会复制到指定输出目录。真实 SMTP 接受、退信、额度和风控仍需使用实际账号核对；隔离回归不代表真实投递验证。

只选择当前登录账号实际加入的群。普通成员能否读取名单由接口与账号实际状态决定，本工具不会提升群权限，也不把权限错误解释成“群里没有成员”。

右上角可切换跟随系统、浅色或深色外观，页面和 Windows 标题栏同步，选择会保留到下次启动。操作成功或失败显示为顶部居中的悬浮卡片，出现或关闭都不挤动页面，可自动收起或手动关闭；打开弹窗后继续悬浮显示并可交互，底部按钮保持可用。任务进度和需要处理的状态仍保留在所属页面。

## 列表默认排序

群聊和排除群按群名，模板库及导入预览按模板名；成员、已过滤成员和本封群收件人按 QQ 号；发送记录、待核实投递及手动排除按收件账号排序（有 QQ 号时使用 QQ 号，否则使用完整邮箱）。默认规则自动生效，无需手动选择：

1. 数字在前，连续数字按数值从小到大，例如 `2群 → 10群`、`a2 → a10`。
2. 英文与中文共用 A–Z：汉字逐字转拼音首字母，与英文同级比较，忽略英文大小写，例如 `A群/阿群 → B群/波群 → C群`，不会把全部中文排在英文之后。同首字母继续比较后续字符和数字；完整键相同按固定 ID 排列。
3. 其余字符按 Unicode 码点从小到大；全角数字属于这一类。

多音字采用固定词库的单字默认读音，不做词义识别；未收录汉字保留原码点，归入其他字符。首字母相同时继续比较后续键，完整键相同按固定 ID 排列；比较忽略首尾空白，空群名按群号定位。完整列表先排序，再搜索、分页；刷新不会因返回顺序变化打乱同名项，已有勾选按账号或记录 ID 保留。移除末页最后一项后停留在有效页，新增记录不会跳回旧末页。群头像支持完整表情与扩展汉字。

发件账号保留账号设置中手动上下移的顺序；实际发送队列、已冻结的分配与日志时间顺序按原有规则执行。这里改变列表显示，不修改 SQLite 中的名单、导出原始顺序、共享历史/排除规则或冷却间隔。

## 本版布局与预计完成时间

全局导航、当前QQ身份、扫码与外观/日志集中在同一条工具栏，保留原蓝灰配色及深色主题。成员页左侧为群目录和名单筛选，右侧为人数核验、成员结果和导出。写信、已发送记录和手动排除统一为左侧配置/维护、右侧正文/结果，两区独立滚动；模板采用卡片库与预览，发件配置采用账号卡片与表单。搜索、全选和跨页选择规则保持原样。

写信模式切换固定在左栏顶部，收件范围与配置在下方单独滚动，按钮不会覆盖内容。扫码弹窗标题与关闭按钮同排，通知浮在视口顶部，不占扫码弹窗的布局空间。搜索框与账号配置字段统一40px，发送参数仍为36px；群聊选中后悬停保持高亮。待核实卡片的复选框与地址同排，表格文字和操作垂直居中。折叠区整行可点击；模板卡片显示两行名称/主题摘要，悬停或右侧预览可查看完整内容。页面、弹窗与展开内容有短暂淡入，开启Windows减少动态效果设置后关闭；动画不影响输入、草稿或发送时序。

正文格式、图片和附件集中到同一编辑工具栏；没有补充输入时隐藏不可用的“全选输入”，输入后自动出现。发送/停止操作位于写信工作区底部、两栏滚动区之外，长正文和配置滚动时始终可用。成功和失败通知统一为顶部居中的悬浮卡片，最多显示3条；普通页面避开主导航，打开弹窗时浮在视口顶部。提示正文超长可单独滚动，关闭键固定在卡片右上方；成功/普通提示4秒、错误7秒，鼠标停留时暂停，键盘也可关闭。提示出现、堆叠、关闭均不改变页面和弹窗的布局；卡片以外区域不拦截点击，底部操作保持可用。错误、待核实和名单不完整等需处理状态继续留在页面。

登录账号与“扫码登录 / 重新扫码”统一在右上角，成员页不再单独显示重复的登录行。QQ 登录失效仍会在任何页面显示，并提示重新扫码。成员获取过程说明正常时折叠，需要核验或有警告时展开；筛选条件、名单与错误保持可见。

成员操作使用一行工具栏，选中成员后才显示“排除所选”“给已选写信”和清空选择。排除群、手动排除、发件账号、模板导出使用同一个按钮切换全选/取消全选，搜索范围外的已选项保留；清空按钮只在存在选择时显示。写信页只显示一次发件账号，发送方式、每封人数、失败策略和两项间隔可展开“发送选项”调整（同账号默认900秒、切换默认60秒）；完整调度规则见本文发送规则部分。 展开后发送方式、每封人数及两项间隔按“标签—控件—单位”三列对齐，控件高度统一为36px；切换逐人发送时仅隐藏每封人数，其他字段位置规则不变。模板编辑中显示更新/另存操作，不再重复“保存为模板”。已发送记录左侧依次放置待核实投递和人工添加/导入，添加/导入默认展开，可收起且不清空输入；右侧专门展示已发送记录。手动排除左侧新增规则、右侧搜索与维护。账号设置采用左侧账号卡片、右侧分组表单，保存和取消固定在底部；发送确认将人数及账号分配与发送参数并排，长列表不挤走确认按钮。

确认发送弹窗显示完整的“预计结束时间”，例如“2026年11月10日14:22:53”，按本机时区显示。弹窗打开期间每秒按“此刻开始发送”更新，关闭或点击确认立即停止；实际收件范围和随机分配不会随时钟改变。已有账号冷却、切换间隔和末批后无需等待均计入，首批前按每封约10秒暂估；恢复中的未完成尝试按原冷却间隔保守估算，查看不会改写冷却。确认超过5分钟会关闭并提示重新确认，防止使用过期名单。

“发送选项”自动保存跳过已发送、失败后继续发送、发送方式、每封人数、同账号间隔、账号切换间隔及展开状态；重开软件后恢复。首次使用仍为跳过已发送、失败后停止、密送每封20人、同账号900秒、切换60秒。空值、小数或越界数值不会覆盖上次合法值；关闭账号切换等待需明确输入0。“名单筛选”自动保存过滤已发送、排除好友、排除群和展开状态，按登录来源及QQ账号隔离，同账号切群继续沿用。目标群自身及当前未加入群不会作为排除群提交；切换目标或群目录短暂刷新不会删除保存的偏好。历史快照不会覆盖上次筛选，更改只影响下次获取，已有名单和邮件范围保持原样。偏好只在本机保存开关、数值和公开群标识，不保存主题、正文、地址或凭据；存储失败会提示，本次操作仍可继续。

发送任务运行时会显示“预计完成时间：2026年11月10日14:22:53”这样的完整本机日期时间，同时保留下一批倒计时。预估使用确认后固定的实际收件批次、账号已有冷却、轮内就绪优先顺序、同账号间隔与切换间隔，两个间隔取较晚期限，不重复相加，末批后不追加等待。首批前按每批 10 秒暂估，之后用本任务已完成批次的平均处理耗时（最少 1 秒），主动等待不纳入该样本。每次批次或调度边界更新运行中预计值，运行中页面计时不会发起额外投递或每秒读取后台。

预计值代表在后续批次继续执行的前提下处理完整队列的时间，不保证精确完成或收件箱送达；网络变慢、失败停止或取消会改变结果。预计时间已到但批次仍在执行时显示“正在更新”，停止或结束后隐藏。应用关闭后不会恢复发送任务；本功能不保存任务、不改变原有冷却池。

## 解除指定成员过滤

截图所示的“排除群重合”现在可在“已过滤”标签中搜索 QQ 号，点击该行“恢复到名单”并确认。程序保留原版本，在 SQLite 保存有调整时间和原过滤原因的新版本；已有勾选会保留，恢复成员须明确勾选，再点击“给已选 N 人写信”并确认替换群收件范围。邮件主题、正文、附件和补充输入继续保留。

恢复仅对当前保存名单生效，重新“获取成员”会按原过滤选项重新计算。全局手动排除、发送前的“跳过已发送”和结果不明投递仍独立生效，不能靠恢复绕过；已发送行可“查看发送记录”并定位该 QQ 号。群重合明细保留原获取时统计，当前过滤总数已扣除恢复人数；Excel“获取说明”记录恢复成员与原原因。调整旧邮件版本不会覆盖同群更新的获取结果。

恢复前可取消，失败时保留确认和原因供重试，处理中禁止重复提交及关闭确认；不会发送邮件。若只是想撤销补充输入，可直接使用输入区的逐条/批量移除按钮。

## 连接账号

成员读取统一使用网页扫码方式。点击右上角“扫码登录”，用手机 QQ 扫描二维码并确认；同一扫码状态保持同一提示，只在已扫码、等待手机确认或过期等状态变化时更新。二维码过期后刷新。页面只收到二维码图片和公开登录状态，不接触 Cookie。

以本次手机确认并通过核验的 QQ 账号登录；即使与当前账号不同，也会直接切换，无需先退出。成功后加载新账号群列表并清空当前选群、成员工作区；新账号不能沿用旧账号的成员选择或过滤条件。取消、过期或扫码验证失败保留原账号，刷新二维码后可重试。

QQ 登录只保留在当前程序进程内存中，不再保存登录文件、自动恢复或显示七天保留期限，已移除“重试恢复登录”和“清除保存的登录”。关闭程序后重新启动需扫码；同一进程内切换页面不影响登录。服务端仍可能提前使会话失效，此时需重新扫码。点击“退出当前账号”立即结束本程序当前 QQ 登录。

升级启动时，只尝试删除旧版固定的 `qq-session.bin` 文件，不读取、解密或复用；文件被占用或无删除权限时仍不使用它，启动不受阻，下次启动再尝试清理。群目录、成员结果、邮件模板、发送记录、排除名单和 SMTP 授权码继续保留。正在编辑的邮件内容及已确认收件范围不会因扫码切换而被静默替换，发送仍须预检及确认；未保存草稿关闭程序后不保留。

更换 EXE 目录继续使用同一 Windows 用户的数据目录。公开名称统一为 `batch-send-email`，仍保留 `com.ahui.qq-group-exporter` 应用标识和既有数据目录，不因改名搬迁、清空数据库或重置 SMTP 凭据。查看新版本需先正常退出旧版，再启动新 EXE；单实例会唤回正在运行的旧进程，不能热更新。

## 目标群与排除群

群列表与右侧内容分别滚动，群很多时无需把整个页面拉到底。群名前的复选框支持同时选择多个目标群；“全选当前群”只作用于当前搜索结果，取消全选也只取消该范围，搜索外已选群保留。“清空选择”清除全部目标。点击群名则切换为查看该单群，要合并多群请使用复选框。每次最多200个目标，超过时保留原选择并提示。改变选择会显示该账号在本机保存的对应单群或组合名单；没有记录时提示获取，不显示其他组合的名单。目标勾选不跨启动记忆，重新勾选相同组合可读取其保存结果，勾选顺序不影响缓存。

获取后群列表显示已知总人数；若服务未提供总数，不把过滤后的数量当作群总数。排除群可选一个或多个，可“全选当前结果”或仅取消当前搜索结果的选择，其他搜索条件下的已选群保留；“清空全部选择”才清除全部排除群。全部已选目标群都不会出现在排除候选中，过去保存的排除偏好仍保留，仅本次不提交冲突项。排除群表示“全部目标群合并名单中，同时也在这些排除群里的人不要导出”。

例如目标群 A 有 1000 名有效成员，排除群 B 有 200 人，其中只有 20 人同时在 A 中，最终导出 980 人；不是直接从 1000 中减掉 200。若再选择 C，已经因 B 移除的人不会重复计数。

多群先取成员并集，按真实数字 QQ 号去重，再统一执行排除群、好友、已发送和手动排除。同一成员即使在多个目标群中，也只出现在最终名单一次、只按首次过滤原因计数、只进入本封候选一次。昵称或名片不同时保留群号排序靠前的目标群资料。好友过滤启用时，同一任务只读取一次好友列表。匹配只使用 QQ 号，同昵称不同 QQ 号不会合并；任何目标群都不能同时是排除群，所有群必须属于当前账号和获取方式。

程序串行读取全部目标群并分别核验，然后统一筛选；“来源群”详情列出各群名、群号、获取人数、参考人数和状态。合并摘要显示去重人数，不把各群参考人数相加。任一目标为部分或待核验时，合并结果也保留对应限制，不能用其他群的重合成员抵消缺失。页面同时保留各排除群获取人数与实际新增排除人数。任一群读取失败或任务取消，均保留上次完整结果，不发布已成功的半套名单。任务时限随目标和排除群数量增加，每群按120秒预算，任务总上限30分钟；超时后可减少群数重试。

## 获取与核验

点击获取后可以取消。执行时限制重复点击，并锁定账号与群选择。取消后，迟到的旧请求不能覆盖新的任务。

| 状态       | 含义                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| 数量一致   | 当前已知参考人数、有效去重人数和刷新条件一致，未发现明确截断。名单仍以获取时为准。 |
| 名单不完整 | 有明确遗漏，例如少于参考人数、无效号码或读取中断。                                 |
| 待核验     | 缺少独立总数、无法确认缓存已刷新、参考人数冲突，或排除群未完成核验。               |

目标群人数核验使用**排除之前**的有效人数；最终导出人数是排除后的剩余人数，两者不应混淆。群成员可能在获取过程中进出，即使数量相同，也不能保证是同一时刻的全量名单。

如果排除群不完整或待核验，已经读取到的重合成员仍可被移除，但可能还有未读取到的重合成员留在最终名单。界面与导出文件会保留这一限制，不会显示为“排除全部完成”。

全部目标成员被合法排除后，剩余 0 人是正常结果；没有取得原始目标名单则不能视为正常空结果。

## 群聊与成员的本机保存

群目录和成员结果保存在 `%LOCALAPPDATA%/com.ahui.qq-group-exporter/data.sqlite3`，更换 EXE 目录不会清空。扫码登录或刷新群列表成功后，更新对应账号的群目录；点击“获取成员”仍会联网重新获取，成功后更新该账号该群的最新成员资料、人数、过滤条件及结果。旧成员退出或资料变化会随新结果整体替换，不是只追加。失败或取消保留上次成功结果；“名单不完整”“待核验”等状态按真实结果保存，不会因落库变为已核验。

每个来源、账号和单群／多群组合独立保留一份最新结果，不受全局最近 20 次历史淘汰影响；另外保留最近 20 次历史版本供固定名单使用，包含获取和明确恢复产生的新版本。当前已登录账号切群时可读取该群本机结果；保存的历史身份和群目录不代表当前登录或权限。退出 QQ 不删除名单和邮件历史，也不会自动展示其他账号名单。数据库有成员和邮箱等业务内容，备份前先退出程序并复制完整数据目录。

## 排除我的 QQ 好友

在筛选区勾选“排除我的 QQ 好友”，然后重新获取名单。默认不勾选；开关变化不会直接改写当前结果。程序先核验目标原始人数，再按“排除指定群 → 排除好友 → 过滤已发送”处理，重合成员只记第一次原因，避免重复扣人数。

好友关系只属于本次获取所用的 QQ 账号，随群和名单版本保存，不会借用其他账号或上次名单的关系。切群、换号或获取新版本不会悄悄改写正在编辑邮件的原名单；调整原邮件成员时恢复它自己的名单版本和原筛选说明。左侧筛选开关沿用当前账号上次选择，仅在重新获取时生效。

勾选后，程序用本次获取的同一登录账号读取一次好友列表，合并好友分组并去重，再判断目标群内每个人是否为好友。好友列表读取失败、缺少必要内容、只返回部分结果或无法确认是否读完时，本次获取失败，旧名单保持不变；不会把未读到的人直接当成非好友，也不会悄悄改用其他标记。取消该选项可按原有流程重试，但新结果不代表已排除好友。旧名单中的关系仍可为未知，需重新获取才能启用排除。

“已过滤”列表显示“QQ 好友”原因及实际排除人数；Excel 同步记录。成员选择、导出和邮件仅使用最终名单，不能通过补充 QQ 邮箱直接加回已过滤好友；需要保留时先明确“恢复到名单”并重新确认收件范围。其他品牌邮箱或 QQ 邮箱别名与 QQ 身份没有可靠映射，不代表已完成全量好友邮箱识别。

未勾选时不读取好友列表。完整好友表只在本次任务内使用，不持久保存、不跨任务或账号复用；本机仅保存这次目标群成员的关系与过滤结果，不提供全好友管理页，也不删除好友、不操作 QQ 客户端。当前按 QQ 网页一次返回全部好友分组的方式读取；页面显示的人数也来自同一份数据，不能独立证明服务端从未漏返。本次尚未用真实普通成员账号核对好友接口和实际结果。

## 已发送过滤与本机历史

勾选“过滤已发送”后，程序先完成排除群与可选好友处理，再从剩余名单中移除本机已有成功发送记录的 QQ 号。同一人不会在群排除、好友排除和已发送过滤中重复计数；人数关系始终为目标有效人数 = 最终人数 + 已过滤人数。

已发送历史是本机全局记录：同一个收件人即使来自不同群或不同提取 QQ 账号，也会命中过滤。程序不会把导出操作当作邮件发送。你可以手工导入或维护历史标记，但人工记录与程序 SMTP 成功记录会保留不同来源。

发送记录和待核实投递均显示原发件账号名称与邮箱，可输入名称或邮箱搜索。账号后续改名、改邮箱或删除不会改写已保存记录。旧版记录、手动添加及导入缺少来源时显示“未记录”，无法从现有账号推断补齐；待核实条目人工核实为已发送时保留原账号。已发送列表仍按收件人去重，同一收件人再次成功后显示最近一次的账号，不是每封邮件的独立流水。

点击顶部“已发送记录”会进入独立页面，与成员提取、写邮件使用同一套导航。页面可刷新、搜索和翻页，粘贴号码或导入 UTF-8 TXT/CSV 添加记录，也可处理待核实投递。删除记录和核实投递都要再次确认；离开页面会取消尚未提交的确认。从顶部导航或成员的“核实投递记录”进入后，可通过返回按钮回到原页面，保留原来的成员勾选、主题、正文和附件。

待核实记录可逐条、整行或通过空格/Enter 勾选，也可“全选本页”“全选全部待核实”或“取消全选（全部待核实）”；选择跨页保留，工具栏显示已选条数。批量“核实为已发送”或“核实为未发送”会先确认本次人数及后果：已发送添加人工核实记录，未发送只解除限制，不会立即发信。全部所选记录在一个事务中核对并提交，任一记录已变化则整批不处理。失败保留选择和确认可重试；刷新会剔除已不存在的项，翻页或离开取消未提交确认但保留选择。提交期间锁定选择及维护操作，避免重复处理。

“搜索待核实投递”按邮箱或提示筛选，与下方已发送搜索分别使用。搜索后可全选或仅取消当前匹配结果，其他搜索范围已选项继续保留；批量核实仍处理工具栏显示的全部已选条数，确认时请核对数量。清除按钮恢复完整列表并返回输入框。改变搜索条件会撤销尚未提交的核实确认。

“已过滤”列表保留 QQ 号、昵称、名片及原因，可检查是与哪个排除群重合、QQ 好友，已有发送记录，还是手动排除。Excel 中也有独立“已过滤”工作表；CSV/TXT 仅包含最终名单，不混入过滤记录。

## 预览和导出

名单可以按 QQ 号、昵称、群名片搜索并分页浏览。当前账号和成员表默认脱敏显示 QQ 号，可点击显示按钮切换完整号码；导出仍保留完整号码。搜索只改变屏幕预览，不改变导出范围。

群、成员、排除群、手动排除、记录、群收件人预览及模板的搜索框可一键清除，清除后继续输入即可再次查找。清除搜索不清空成员或排除项选择；部分列表会提示范围外仍有已选项，只有明确清空全部才取消它们。

通过原生保存对话框选择文件和保存位置。导出固定使用当前页面对应的名单版本，不会改用后台最近获取的其他群，不重新读取群，也不会因当前搜索条件悄悄少导。每个单群及多群组合的最新版本持续保留；旧版本既不在最近 20 次历史内、也不再是该群最新时，需重新获取。获取和记录时间统一显示完整年月日及时间。

| 格式  | 内容与注意事项                                                                                                                    |
| ----- | --------------------------------------------------------------------------------------------------------------------------------- |
| Excel | 推荐格式。QQ 号和文本不会被解释成公式；附有“获取说明”工作表、排除摘要和好友关系明细。                                             |
| CSV   | UTF-8 BOM，便于中文 Excel 打开；含 QQ 号、昵称和群名片。可疑公式文本会增加单引号前缀。Excel 自动识别号码格式的行为不由 CSV 控制。 |
| TXT   | UTF-8 无 BOM，只保存最终 QQ 号，一行一个。全部排除时为空文件。                                                                    |

导出“部分”或“待核验”结果时，默认文件名有相应标记；执行了群排除、好友排除或历史过滤时另有“已过滤”或“排除待核验”标记。保存失败不会用半成品覆盖原文件；若文件正被 Excel 占用，请关闭后重试或改用其他文件名。

## 手动排除个人或多个账号

在成员表点击一行右侧“排除”，或勾选多个人后点击“排除所选 N 人”，确认后即时生效，无需重新获取。主导航“手动排除”也可直接粘贴 QQ 号或完整邮箱，推荐每行一个，支持中文或英文逗号、分号分隔；备注可选。它是本机全局规则，对所有群、提取账号、补充邮箱和快捷发送都生效，不会伪造已发送记录。

QQ 号对应 `QQ号@qq.com`；完整邮箱按规范化地址匹配（域名忽略大小写、本地部分保留），不推测外部邮箱或别名属于谁。每次最多添加 10000 个非空项、512 KiB 文本，备注最多 500 字且不能含控制字符。重复项保留原备注和时间；非法项会显示数量、保留原输入供修正，已保存的合法项无需再次添加。

当前原始名单不被改写；在已有群、好友、已发送过滤之后，实时叠加手动排除，重合成员只记一个原因。当前人数、成员勾选、导出、群邮件与快捷发送使用同一规则。“已过滤”和 Excel 会标明手动排除人数与原因。可搜索账号/备注，逐行、本页或跨页“全选当前结果”并确认移除；“取消全选（当前结果）”仅取消搜索范围内选择，“清空全部选择”才取消全部已选。取消不修改数据，移除不会自动勾回成员，也不会解除其他过滤和待核实限制。

翻页会保留勾选并撤销旧移除确认；提交期间暂时锁定翻页，避免维护范围在处理中变化。

发送、等待下一轮、停止中或获取成员时，名单可查看和搜索，不能添加或移除。规则改变后需重新确认发送。保存失败保留输入供重试；若提示已经保存但名单刷新失败，程序补读本机排除列表，必要时手动刷新，不能继续沿用旧确认。手动排除不会删除 QQ 好友、改动 QQ 客户端或立即发信。

## 快捷给一个或多个邮箱发信

打开“写邮件”选择“快捷发送”，无需登录 QQ 或选择群。把完整邮箱粘贴到“收件邮箱”，每行一个，可用逗号、分号或空白分隔；修正不完整地址后，填写主题和正文，或“选择模板”预览后应用，再点击发送核对实际人数。一个地址即给一人发送，多个地址沿用密送分批、已发送跳过与二次确认。

“快捷发送”和“群成员发送”各自保留输入的邮箱，不混用群收件人；主题、正文、图片、附件、模板和发件设置共用。切换模式不会清空内容，应用模板不改变任何收件范围。只有当前模式参与发送，快捷模式仍执行全局手动排除、已发送跳过和待核实阻止；确认中可展开本次手动排除的地址，全部被过滤时不启动任务。临时快捷输入与未保存草稿仅本次运行保留。

“全选输入”会选中当前模式手工填写的完整邮箱文本，便于复制或替换；不会勾选或更改已绑定的群成员。

## 从群成员开始写信

在最终成员表中点击整行或复选框选择收件人，行获得键盘焦点后也可用空格或 Enter 切换，再点击“给已选成员写信”；也可直接给过滤后的全部成员写信。拖选文字、点击行内按钮不会改变勾选，禁选成员仍不能通过整行操作加入。支持本页全选、跨页全选成员或当前搜索结果；再次点击取消全选，仅取消当前搜索范围，保留其他搜索结果已选项。清空成员选择会取消全部勾选。读取发送状态期间或待核实成员不能通过批量操作选入，读取失败可刷新重试。搜索只是帮助选择，**给全部成员写信仍使用完整最终名单**；要仅发给搜索结果，先明确选中匹配项，再给已选成员写信。“已过滤”页可核对原因、逐人点击“恢复到名单”，确认后生成新的保存版本，再在“筛选后成员”中勾选。手动排除行的“移除手动排除”会定位到对应全局规则，由用户确认移除。

写信页区分“筛选后名单”与“本封已选”，来源群和名单时间保持可见，排除群与筛选人数可展开“筛选详情”核对。可展开群收件人列表检查姓名、QQ 号及候选邮箱，或点击“调整群成员”返回这封邮件的来源群和原名单版本，并恢复本封已选成员；返回时主题、正文、附件和发件设置保留。若原账号已退出或群已不在当前账号中，仍可调整已保存名单，获取新成员需先登录对应账号。

切群、修改筛选条件或重新获取后，本封邮件仍使用先前明确确认的名单版本，不会自动换人。若要改用新的范围，需要从成员表重新发起并确认替换；取消替换会继续使用原收件人。数据库保留每群一份最新结果及最近 20 次历史；绑定的旧版本两处都已不再保留时，发送会要求重新确认名单。

## 写信与 SMTP 投递

群收件地址按 `QQ号@qq.com` 生成；QQ 号并不保证已经开通 QQ 邮箱，请核对收件人。补充邮箱填写完整地址，支持 QQ、Gmail 等邮箱，推荐每行一个，例如：

```text
someone@qq.com
someone@gmail.com
```

也可用逗号、分号或空白分隔。补充栏不自动把裸 QQ 号补成邮箱；程序合并去重计数，不完整的地址必须修正，不会静默丢弃。历史记录的导入仍可填写 QQ 号。补充地址不由群成员资格证明；绑定群名单时，不能靠手动输入重新加入源群中未选中或已过滤的 QQ 号，可点击对应地址旁的“定位成员”，直接进入原名单、原群和对应标签并搜索该号码；也可逐条“移除地址”或“移除全部受阻地址”。无效地址提供逐条/全部移除，只移除指定输入及重复项，保留其他原文。

在“发件设置”中可添加、编辑、删除多个邮箱账号，最多 20 个。点击“添加账号”，填写可选账号名称、SMTP 服务器、SSL/TLS 或 STARTTLS、端口、登录账号、发件地址及授权码，再“保存配置”。QQ 邮箱通常先开启 SMTP 并申请授权码；同一 SMTP 登录和发件身份不能重复添加。列表可上移/下移方便管理，发送默认随机均分；删除要确认，不清空共享历史或排除名单。旧版本保存的单账号会自动保留为默认账号。

每个账号独立加密保存授权码，下次启动无需重填；编辑时密码框始终不回显，留空保留匹配凭据，填写新码并保存才替换。当前界面只使用已保存账号发送，未保存的编辑不会自动用于本次任务；关闭设置、切换账号或删除另一账号后保留当前窗口内的输入，可明确点击“放弃未保存修改”。新增账号默认勾选参与本次发送。改动认证身份后需要对应的新授权码；缺失或无法解密会明确提示，可重新填写并保存。

已保存授权码绑定账号标识以及服务器、端口、加密方式、登录账号和发件邮箱，不能借用其他账号的密码。“清除已保存授权码”只清除正在编辑账号的凭据，保留其他账号、QQ 登录、名单与历史。QQ 退出不清除发件设置；密文不能迁移到另一 Windows 用户或电脑。保存、清除或删除遇到部分完成时会说明实际结果并重新读取目录，请按提示处理，不重复猜测是否成功。

## 多账号平均分配

写信页“本次发件账号”默认勾选全部已保存账号，可全选、取消全选或单独勾选。必须至少选择一个；默认随机均分，不需要选择规则，勾选先后和账号在列表中的位置不决定谁多分一人。账号与收件人数量不等时，只按实际待发送人数平均分配。

| 选中 5 个账号时的实际收件人数 | 随机分配后的数量组合（账号归属随机） |
| ----------------------------- | ------------------------------------ |
| 1                             | 1、0、0、0、0                        |
| 2                             | 1、1、0、0、0                        |
| 3                             | 1、1、1、0、0                        |
| 8                             | 2、2、2、1、1                        |
| 10                            | 2、2、2、2、2                        |

程序先去重、应用全局手动排除和已发送过滤，再随机打乱实际收件人和账号的分配顺序。设剩余 N 人、选中 M 个账号，每账号先分 `N÷M` 的整数部分，余下随机选取不同账号各多一人，保证人数最多相差 1；本次分到 0 人的账号不发送，也不要求为本次提供凭据。每次点击发送准备一份新的随机计划，确认后使用同一份计划，不会重新打乱；不承诺不同任务的随机结果一定不同。

确认发送会列出每账号邮箱、收件人数及预计邮件封数。逐人模式是每人一封；密送分批是在各账号自己的名单内按“每封人数”拆批，例如 8 人、5 账号、每封 20 人时分配 2/2/2/1/1，共 5 封，改逐人则共 8 封。确认分配不发信，只有“确认发送”才启动。

所有账号共用已发送记录、待核实投递与手动排除。已排除、已发送或待核实的同一地址不会因换账号被当成新收件人；“跳过已发送”仍按开关执行，待核实始终阻止。运行前先校验全部实际参与账号，任何一个不可用则不开始投递。账号、顺序、授权码、选中范围、发送模式或每封人数改变会使旧确认失效，需重新准备。

发送按轮次串行执行，每轮各有任务账号最多一批。按预检固定顺序优先查找已就绪账号，仍在冷却的账号先跳过；本轮没有可发账号时才等最近到期的账号，B 不必等待 A 的900秒冷却，但仍需满足本次配置的账号切换间隔。各账号自己的收件分配与名单顺序保持不变，账号尝试顺序可因冷却先后变化。同一账号从上批结果处理结束起计算“同账号间隔”，其他账号耗时计入冷却；本轮尝试完再进入下一轮，已发完账号不参与后续等待。只有一个账号时，每批就是一轮；最后一轮后不再等待。失败后停止或继续未尝试批次按原开关处理，不自动换号重发、重新平均或把不确定结果当成功。停止会结束等待并阻止后续批次；数据库登记等待期间也会检查停止，已进入的当前 SMTP 交互按原规则完成后记录结果。

“账号切换间隔”可填写 0—3600 的整数秒，默认 60 秒，填 0 关闭。同账号间隔仍默认900秒，支持1—3600整数秒；两项从上次结果处理完成起计算，取较晚时间，不是900+60秒。首封没有切换等待，同一发件邮箱连续使用只检查同账号冷却。取消再发保留当前程序运行期的切换限制；正常重启只恢复数据库中的同账号冷却，切换计时从新进程重新开始。确认窗口显示两项，修改后需重新确认。

正文支持加粗、斜体、下划线、项目列表和撤销。在正文点击插入位置后，可直接 Ctrl+V 粘贴截图，也可点击“插入图片”选择本机图片。支持 PNG、JPEG、GIF、WebP，每封最多 10 张、单张不超过 5 MiB，图片每边不超过 8192 像素且总像素不超过 4000 万；超限时请先缩小图片。图片会以内嵌方式随邮件发送，收件人无需访问本机文件。普通文字粘贴按纯文本处理，不自动下载网页中的外链图片；预览不执行脚本或加载外部资源。

界面和邮件预览的默认右键菜单已关闭。复制、粘贴和撤销可分别使用 Ctrl+C、Ctrl+V、Ctrl+Z，正文仍支持粘贴图片。

图片下方可移除指定图片，撤销可恢复刚才的编辑；切换成员、写信和记录页面会保留当前草稿。未另存为模板的正文图片、附件、正文均不持久保存，关闭程序后需重新填写。本次编辑的图片撤销缓存最多 64 张、64 MiB；缓存满时可先在其他位置保留文字，重新打开程序后插图。普通附件通过文件选择器加入，最多 10 个；当前正文图片与普通附件合计不超过 18 MiB 原始大小，实际编码后邮件还会变大，仍受邮箱服务限制。

默认使用“密送分批”：同一封邮件可投递给多个 BCC 收件人，不向彼此公开地址。默认每封 20 人、同账号间隔 900 秒（15 分钟），大名单自动拆成多封；20 只是产品默认批大小，**不是 QQ 官方每封人数上限**，应按发件账号规则调整。也可选择“逐人发送”。准备前显示候选人数，确认前才按真实待发送人数计算预计邮件封数。

点击发送后，后台先应用全局手动排除，再从真实全库历史按“跳过已发送”筛选，摘要显示实际待发送人数、群成员与补充邮箱数量、已跳过人数、预计封数以及失败策略；没有待发送收件人时只提示，不打开确认或启动任务。只有再次确认后才开始真实 SMTP 投递，发送使用同一份已确认名单，不会再过滤一次并改变人数。整群筛选过程留在“筛选详情”，不与本次人数混在一起。后台从已存名单重新校验范围，不能发送不属于该快照最终成员的群收件地址。

每次点击发送都会重新准备收件计划，确认有效期为 5 分钟。收件范围、发送模式、跳过开关、手动排除或历史记录发生变化后需重新确认；普通刷新记录不会改变历史版本。发送结束后再次发送同样重新读取历史，不沿用上次人数。准备期间锁定草稿和导航，避免确认的范围被更改。

“失败后继续发送”默认关闭，失败时停止后续批次。需要时可勾选，表示跳过失败的整个批次并继续后续批次，不自动重试，也不把失败批次拆开重发；结果不明确的收件人仍进入待核实并禁止重发。“同账号间隔”默认 900 秒（15 分钟），从该账号上一批结果处理结束起计时；它限制同一账号再次发送；“账号切换间隔”默认 60 秒，支持 0—3600 整数秒，0 表示关闭，切到其他发件邮箱时从上批结果处理结束计算。两项取较晚的可发送时间，不叠加等待。首封和连续使用同一邮箱不增加切换间隔。等待区显示待发账号、轮次、全局批次序号及距离下个可发批次的剩余时间；归零后由后台检查并投递，不表示已被服务器接受。首轮也可能因该账号上次任务尚未冷却而等待。正在投递时不显示等待倒计时，最后一轮后不再等待。等待期间点击停止立即取消等待；正在投递时需等当前一封 SMTP 交互结束后停止后续批次。默认间隔仅为程序设置，不保证避开邮箱服务的额度或频率限制。

服务器确认接受才记录成功；它不保证最终进入收件箱，也不保证没有后续退信。页面成功、失败、跳过均按收件人数统计，失败明细供核查。发送结束后可返回成员表查看本机最新“已有发送记录／待核实／无发送记录”等状态；待核实优先显示，不能按未发送直接重试。状态反映本机记录，不能证明最终送达，也不会重新改写获取时的过滤结果或导出人数。

网络中断或程序退出可能导致“服务器已收，但本机没有收到确认”。这类收件人会在本机历史的“待核实投递”中显示，并禁止再次发送，即使取消“跳过已发送”或开启“失败后继续发送”也不能绕过。请先向发件服务核实，再逐条或批量“核实为已发送”或“核实为未发送”。前者作为人工核实历史参与过滤；后者仅解除重发阻止，不会自动发送。程序只允许一个实例，重复打开 EXE 会回到已有窗口。

## 取消、重发与账号冷却池

默认间隔 900 秒（15 分钟）。A 完成一批后取消，已经触发的冷却仍保留；50 秒后重新发送，A 继续等待约 850 秒，不重新等满 900，也不立即发送。B 若从未尝试且本轮有分配，可以先发。取消等待不更新期限，任务正常结束后同样保留该账号的剩余冷却。

旧版未保存分账号冷却，升级前的发送无法从共享收件历史准确回填；冷却池从新版登记的投递开始保留。冷却按规范化发件邮箱保存到本机 SQLite，重排、更名、改授权码或删除后重新添加同一邮箱不会重置。正常重启程序后继续剩余时间；降低新任务间隔不能缩短已经生效的期限，新的间隔在后续真实尝试后生效。只预检、取消确认或尚未轮到登记的账号不触发冷却；实际投递准备已经登记后，若本地收件预留失败，即使尚未连接 SMTP，也会保守保留该账号这一次登记期限，不从失败时刻延长。

成功和已尝试但结果失败/不明的账号都会冷却，冷却不会代替待核实投递保护。如果程序在 SMTP 交互中异常退出，恢复时对未完成的尝试保守冷却一个原间隔并固定保存，后续正常重启不会不断续期；冷却存储不可用时阻止继续投递并明确提示，不当作已经冷却。

### 等待与弹窗操作

发送进度处在等待阶段时，可点击“跳过本次等待”立即放行当前指向的下一批；适用于同账号冷却、切换间隔或两者同时生效。只跳过这一次，不改变输入的间隔、不清空本机任何账号冷却；后续批次及取消后重新发送仍使用冷却池。新一批处理完成后照常记录冷却。发送中、停止中及任务结束不提供此按钮；重复点击和旧等待请求不会放行未来批次，跳过处理中仍可停止后续发送。

发送确认、发件账号、模板、导入预览、日志及成员恢复/排除确认弹窗统一保留底部操作区。内容较长时只滚动中间正文，取消、保存、导入、确认等按钮始终位于弹窗底部，不必滑到全文末尾。

## 文本链接

在写信页选中同一段落内的文字，点击工具栏“链接”或在正文按 Ctrl+K，填写完整地址后确认。没有选字时插入到光标处，显示文字留空则直接显示地址。把光标放在已有链接中，再打开链接弹窗即可修改；“移除链接”只去掉链接，保留原文字和格式。取消或 Esc 保留正文与选区，插入、修改和移除可用撤销恢复；新输入的文字不会继续带入刚插入的链接。

仅允许完整的 http://、https:// 或单地址 mailto: 链接，不猜测协议，不访问目标网址。无效地址保留原输入并在字段下提示；跨段、图片或多条链接混选时需重新选择，原文不变。编辑页点击链接仅定位光标。预览显示链接文字及完整目标，可选择复制但不能直接跳转，实际邮件保留可点击链接；纯文本邮件在显示文字后补充目标地址。

模板保存、应用、导入与导出沿用原格式并保留合法链接，无需迁移数据库。旧版本会清除文本链接，升级前已被旧版删除的网址无法还原；包含链接的模板请用 v1.0.1 或更新版本编辑和交换。

## 邮件内容模板

在写信页点击“保存为模板”，输入名称即可保存当前主题、正文和正文图片。附件默认不保存，需要时勾选“同时保存附件”。不保存群成员、补充邮箱、筛选、发件设置或发送参数。主题与正文允许留空作为片段，但真正发送仍按原规则校验。

“选择模板”中可按名称或主题搜索，点选后预览，再应用。应用会替换主题、正文、正文图片和附件整套内容；模板没存附件时，当前附件也会清空。有原稿时需确认，取消保留原稿。收件范围、补充邮箱与所有发件/发送设置保持不变。

应用后随意修改邮件，不会自动更新原模板。“更新模板”才覆盖已选模板，“另存为模板”创建新模板；保存前可重新决定是否包含附件。管理界面提供新建、编辑、重命名、复制和删除。新建/编辑进入当前写信工作稿，替换前同样确认；删除需确认，不会删除已经应用到当前邮件的内容。预览、保存、应用均不发信，发送仍需原来的二次确认。

模板搜索显示匹配数与总数，可随时清除。填写保存、重命名或复制名称后可按 Enter 提交；使用中文输入法时，确认候选词不会触发提交。删除和邮件发送继续使用明确的确认按钮。

图片与已保存附件有独立副本，原文件删除或移动、重启程序后模板仍可用；切换模板不会夹带上一份图片/附件。模板失败时可重试，原模板不被清空。发送中、图片登记中或模板处理中暂时不能更改内容，避免重复操作。

最多 200 份模板，名称 1—80 字、主题最多 200 字、正文 2 MiB；资源仍是最多 10 附件、10 正文图片，合计 18 MiB，单图 5 MiB，支持格式与尺寸限制不变。模板保存在现有 SQLite 内，包含内容副本，备份整个应用数据目录即可。

当前数据库 schema 为 5：保留既有模板、手动排除、群目录与每群最新结果表，在发送与待核实记录中新增发件邮箱、账号名称快照列。0/1/2/3/4 的旧数据库同事务升级，不清空历史、模板或设置，并从尚存快照回填每群最新数据；此前已淘汰的记录无法恢复。旧快照缺少的新字段按兼容默认值读取，不改写原记录。使用新版前先退出旧版并备份整个数据目录（含可能存在的 WAL 文件）；升级失败整体回滚。schema 4 及更早程序不能读取 schema 5，回退需保留新数据另存，再恢复升级前完整数据目录备份，不要手动修改数据库版本号。

## 模板导入和导出

打开“写邮件 → 选择模板”：

1. 导出一份：点选预览后点击“导出当前模板”。导出多份：勾选左侧复选框，点击“导出已选 N 个模板”。可按搜索结果全选或取消，范围外已选项保留；“清空导出选择”才清除全部勾选。
2. 在原生保存窗口选择位置，保存为 `.qqmailtemplates` 文件。取消保存不提示导出成功。包内含模板主题、正文和实际图片/附件字节，不依赖原电脑文件路径。
3. 点击“导入模板”，在原生打开窗口选择包，检查模板、主题、图片和附件数量。同名按去除两端空白后的完整名称匹配，区分大小写；默认“另存为副本”，可选“跳过同名模板”或“覆盖同名模板”。跳过也会跳过同包中前面已出现的同名项；副本自动使用唯一名称。
4. 覆盖与本机同名项前须勾选确认，整套主题、正文、图片及附件都会替换。包内重名或本机同名不唯一时禁止覆盖，可改选副本或跳过。点击“确认导入”后整批保存，任一校验或保存失败整体不改动原库；可恢复的保存失败保留预览供重试。

导入预览最多保留 5 分钟；过期、模板库在预览后发生变化时需重新选文件。取消、关闭或重新选文件释放旧预览，处理中暂时锁定操作，避免重复提交。成功导入只更新模板库，当前邮件内容、图片、附件、收件人与发送设置保留；需明确“应用模板”才替换当前邮件。

格式为 UTF-8 JSON 无 BOM，`kind=qq-mail-templates`、`version=1`，资源使用 Base64。只接收此版本且字段完整的格式；包含不识别字段、无效图片、缺失 CID 或超限时整包拒绝。文件最多 128 MiB，正文加解码资源合计最多 80 MiB，最多 200 份，单模板仍受原有数量与 18 MiB 资源限制，超限可分批导出。包是可读内容备份，包含真实邮件内容，请妥善保存；不含收件人、SMTP 配置/授权码或 QQ 登录，可跨电脑导入。

## 查看诊断日志

“全选日志”可选中当前显示的只读文本，再用 Ctrl+C 复制；不会把未显示的历史日志一并选入。

新版启动后自动记录。点击右上角工具栏“查看日志”，可只读查看当前日志最近最多 200 条，支持刷新、失败重试；发送期间也可查看，不会暂停或重发邮件。仅读取最近最多 256 KiB，截断时会提示，正在写入的半行不展示。需要完整日志或历史备份时，点击“打开日志目录”，可在资源管理器查看 `%LOCALAPPDATA%/com.ahui.qq-group-exporter/logs`。查看和刷新不会清理日志。当前文件是 `app.jsonl`，历史文件为 `app.1.jsonl` 至 `app.4.jsonl`；每份最大 5 MiB，最多保留 5 份，按大小轮转并循环覆盖旧备份。备份编号不代表先后顺序，请按文件内 timestamp 或修改时间查找。文件为 UTF-8 无 BOM、每行一个 JSON 对象。

记录任务阶段、命令结果、耗时和安全错误分类，不保存正文、主题、完整收件邮箱、密码、授权码、Cookie、二维码、原始响应或完整 URL。前端故障只保留错误类型、包文件名与行列；读取和轮询成功会采样，避免大量重复信息。日志无法写入时会提示，其他操作照常；后续事件最多每 10 秒重试一次日志写入。

SMTP 日志按 job_id 和 batch_index 关联同一任务与批次，包含服务器、端口、TLS、人数、耗时、错误分类、SMTP 状态码、扩展状态码（如 5.7.1）和脱敏后的服务端错误链；不启用原始协议跟踪，不记录 AUTH、邮件内容或完整地址。成功、失败、跳过、取消及本地结果保存失败分别记录；冷却等待开始记录下个待发批次序号、间隔和预计截止时间，每秒倒计时不写日志。诊断信息不改变原有待核实与继续发送规则。 SMTP 状态为 550 且服务端明确返回 Too many attempts 时，页面提示“发送过于频繁，请稍后再试”，原因保留在未成功项中；其他 550、认证或网络错误不套用频率提示。详细脱敏响应继续写入日志，不改变原有投递判定。

需要排查时先重新启动新版，再复现一次并查看对应时间。旧版未记录的历史错误无法恢复；日志不代表 SMTP 接受或收件箱送达，本次也没有执行真实 SMTP 投递验证。日志在数据库之外保存；现有 schema 5 用于发件账号归属快照，本次布局与预计时间不需要迁移；不要为修日志而删除数据库。

点击底部“检查更新”可立即查询本项目的 GitHub 正式 Release，按钮在检查期间禁用，防止重复提交；底部操作固定可见，不必滚到正文末尾。结果区分“发现新版本”“当前已是最新正式版本”“项目尚无正式发布版本”及网络、限流、超时等失败状态。失败后可重新点击检查，不会把失败显示为最新版，也不会覆盖上次成功检查记录。版本按语义版本比较，不以字符串或发布时间推断。

发现新版本后，页面展示纯文本发布说明及“前往下载”按钮；按钮只在系统默认浏览器打开本项目对应发布页，程序不会自动下载、安装、执行或替换 EXE。请核对发布正文中的 SHA-256，完全退出旧版并备份完整数据目录后再运行新版。Tag、发布资产和源码之间的对应关系及实际验证记录见 [发布说明](release-notes/v1.0.0-zh.md) 与 [VALIDATION](../VALIDATION.md)。

程序启动后立即静默检查一次，每次检查完成后再等待一小时，无论成功或失败都不会密集重试；打开或关闭关于页不另建后台任务，电脑休眠错过的检查不会补跑。手动与后台并发检查共用同一次请求。后台不弹出通知、不暂停成员获取或发送，检查结果可在关于页查看。

更新检查只访问公开 GitHub 发布元数据，不读取或上传 QQ 会话、群成员、地址、主题、正文、SMTP 凭据或 SQLite。离线时仍可使用原有本机功能；检查结果及错误仅保留本进程，不等同于持久更新任务。

## 常见问题

- **二维码过期**：刷新二维码后重新扫码。等待手机确认和二维码过期是不同状态。
- **网页登录失效**：重新扫码后再获取；已经完成的本次结果仍可导出。暂时网络故障可先重试当前操作；程序不保存或恢复已关闭进程的 QQ 登录。
- **无群权限或已退群**：刷新群列表、重新选群，或检查当前账号。
- **触发限流或额外验证**：停止密集重试，按平台要求等待或完成验证。
- **SMTP 返回 `550 Too many attempts`**：邮箱服务认为发送尝试过于频繁。可停止后续发送并按服务商要求等待，再核对发送记录；日志没有提供统一冷却时长，900 秒间隔也不保证不再触发。服务器接受仅表示收到邮件提交，不等于收件箱已送达。
- **好友关系无法确认**：本次名单未更新，旧结果保持原有过滤范围；重新获取后再核对，或取消好友排除重试。不要把旧结果当作本次已完成好友排除的结果。
- **人数不同**：检查来源、获取时间、人数变化、无效记录和刷新状态，必要时重新登录并获取。

正常关闭程序会清空当前内存 QQ 会话，重新启动需扫码；主动退出立即清空当前登录。用户导出的文件、账号隔离的群目录、每群最新成员结果、最近 20 次历史及过滤快照、邮件模板、发送历史、待核实与手动排除记录继续保留。重启可查看最近结果；读取新名单前必须完成扫码核验。旧结果中的未知来源显示为历史来源，原标识不改写成网页获取结果。数据库位于 Windows 当前用户的应用数据目录 `%LOCALAPPDATA%/com.ahui.qq-group-exporter/data.sqlite3`。删除数据库会丢失名单与已发送过滤依据，应先退出程序再备份；程序不保存 QQ 登录文件。本工具不包含自动加好友功能。

## 邮件标题、正文与垃圾邮件判定

没有一段固定标题、正文或随机文字能够保证邮件进入收件箱。随机插字、堆叠关键词会降低可读性；应使用真实明确的标题、可识别的发件人和与收件人预期相关的正文，不使用误导性回复标题或隐藏内容。

只向同意或合理预期接收邮件的对象发送，提供容易使用的拒收方式，并将拒收地址加入共享排除名单。自有域名应按邮箱服务商要求配置 SPF、DKIM 和 DMARC；使用托管邮箱时按服务商要求配置和使用。实际投递还受账号/域名信誉、退信、投诉、服务商额度及收件方规则影响；多账号随机均分只分配工作量，不保证送达率，也不能代替服务商许可。

## 多群导出与写信边界

多群成功结果及每个来源群的原始成员归属保存在同一份 SQLite 快照，后续获取同一组合更新其最新版本；各单群原有结果独立保留，不会被合并名单覆盖。群目录只显示真实群，不新增虚构的合并群。SQLite 结构版本不变，旧单群结果继续可读。

多群导出沿用 Excel、CSV、TXT 格式，文件名以“多群合并”标记；Excel 获取说明增加各来源群与核验状态，CSV/TXT仍只输出去重后的最终名单。大于10000人的完整结果仍可查看和导出，发送状态自动分块读取；单次写信保持原有10000人上限，请先勾选部分成员再“给已选写信”。

从多群名单进入写信页，来源详情与确认弹窗展示真实群名和群号；“调整群成员”返回原群组合及原名单版本。后台按固定快照验证全部成员与补充地址，不能将已过滤或未选成员借补充邮箱加回。改变群选择或重新获取不会替换正在编辑的邮件范围，明确替换时仍需确认。多账号随机均分、共享历史／排除、同账号900秒和切换60秒默认值保持原样。
