# 扫码切换账号与移除登录恢复验收

作者：ahui

日期：2026-11-11

## 问题、范围与业务行为

旧流程在扫码成功后用当前 QQ 号检查新账号，因此不同账号被拒绝，要求先退出。旧版七天只是本机凭据保存上限，不能决定 QQ 服务端接受期限。本次按用户要求允许本次已授权扫码直接切换账号，并完整移除 QQ 登录保存、启动恢复及其按钮。

本次扫码真实身份、群列表及本机目录保存均成功后，原子替换当前连接、账号和群目录；同账号重复扫码也可刷新。切换时清空当前选群、成员工作区和旧任务，不能混用其他账号的名单。取消、二维码过期或验证失败保留原连接。较早扫码或取消后的迟到响应不能覆盖当前账号；运行中的成员获取和邮件任务仍受原有操作锁保护。

QQ Cookie 仅在当前 Rust 进程内存中使用，继续遵守服务端 Cookie 域、路径与有效期。新进程始终未登录，关闭程序后需重新扫码；不承诺任何固定有效天数。明确认证失效撤下账号、群目录和当前名单，所有页面显示重新扫码提示。网络、权限和业务错误不自动认定为认证失效。

移除“重试恢复登录”“清除保存的登录”和七天说明。启动仅尝试删除应用数据目录固定的 `qq-session.bin`，不读取、解密、复用或递归删除。缺失文件忽略，文件占用或权限错误只记录安全日志，不阻止启动，下次再尝试；即使清理失败也不会使用旧凭据。

SQLite 群目录、成员结果、模板、发送记录、排除名单及 SMTP 授权码继续保留。扫码切换不会静默替换正在编辑的邮件正文、图片、附件或明确冻结的收件版本；发送仍须原有预检与确认。关闭程序不保存未保存草稿。
