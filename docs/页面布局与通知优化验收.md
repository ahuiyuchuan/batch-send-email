## 目标与依据

按用户要求重构页面设计、组件和交互，保留全部现有业务；配色以用户最后明确的要求为准，继续使用原蓝灰配色及深色主题。只验收1920×1080，不增加其他分辨率测试。

页面采用单行导航、清晰的区域边界、输入/结果分区、数据字号层级和分组表单；延续精简交互原则，不增加Three.js。历史记录见[前端简化重构验收](前端简化重构验收.md)。

现有React 19、TypeScript、Vite 7、Tauri 2、Rust及SQLite技术路线不变。已按当前项目规范使用UTF-8、必要的职责/业务边界注释、原生语义和现有图标库；Java手册的通用命名、注释和验证原则适用，Java语法、Javadoc和MyBatis条款不适用于本项目的React/TypeScript/CSS/Rust文件。

## 问题分析与完成内容

原有页面主要沿用纵向表单，配置、名单和正文竞争同一滚动空间；仅改变配色无法改善操作。原通知位于右下角，即使预留距离，长内容或多条通知仍可能挡住操作。修复根因是划分稳定操作区域，让通知占独立布局空间。

| 改动 | 用户体验 | 开发者与智能体体验 |
| --- | --- | --- |
| 内嵌单行导航与统一工作区边界 | 导航、身份、扫码及应用动作位置稳定 | 沿用AppToolbar/WorkspaceHeader，保留名称和状态语义 |
| 成员页侧栏容纳群目录和名单筛选 | 目标和过滤在同一区域；右侧专注核验、选择与导出 | 原FilterOptions仅移动位置，参数和事件保持原样 |
| 写信页配置/正文分栏 | 左侧选择范围、账号和发送参数；右侧持续编辑；两栏独立滚动 | WorkbenchLayout只负责布局，不复制草稿、任务或名单状态 |
| 写信底栏位于滚动区之外 | 长正文或长配置不改变发送/停止按钮位置 | 不依赖覆盖正文的浮层或动态高度计算 |
| 记录/排除维护与结果分栏 | 记录左侧核实和添加/导入，右侧搜索结果；排除左侧新增，右侧维护 | 三页共用带名称的aside/region，键盘可聚焦滚动区 |
| 模板卡片库、账号卡片和分栏确认 | 预览与导出选择独立；账号和配置并排；发送人数/分配与参数并排 | 沿用ID、原生checkbox及aria-pressed；底部确认区仍由DialogLayout统一管理 |
| 顶部独立通知栏 | 工具栏下方或弹窗标题下方显示，不覆盖业务控件；关闭后不留空隙 | 单一Sonner实例与宿主迁移，保留去重、计时、主题和朗读语义 |

通知同时可见最多3条，页面通知区最大184px、弹窗内160px，超长时仅通知区内部滚动。无可见通知时不占空间。原成功/普通4秒、错误7秒、手动关闭和同类去重规则保留。原生dialog属于浏览器top layer，通知仍需迁入当前最上层dialog，不能只调整z-index。

写信左侧模式栏吸顶，聚焦滚动预留64px；账号选择列表内部滚动。历史添加/导入默认展开，可自行收起，收起不卸载或清空输入。账号配置的列表与表单分别滚动；发送确认扩大为双栏，保留包括0人账号在内的原分配信息。危险确认、待核实、失败重试、名单不完整及凭据异常继续可见，没有用删提示替代错误处理。
