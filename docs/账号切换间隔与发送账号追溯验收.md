# 账号切换间隔与发送账号追溯验收

作者：ahui

日期：2026-11-09

## 本轮范围与验收口径

为多账号发送新增默认60秒的可输入切换间隔，在已发送和待核实记录中保存并显示实际发件账号，检查四个主工作区及其设置、模板、选择、确认、取消、错误重试和窄窗布局。本轮不连接真实QQ或SMTP，不读取或升级用户真实数据库。前轮登录恢复、模板导入导出、群目录和每群最新结果持久化、全选、多账号随机均分、共享名单和900秒独立冷却规则继续保留。

## 业务行为

- “同账号间隔”仍默认900秒，支持1—3600整数秒；冷却以规范化From邮箱为键，继续跨取消、终态、新任务和正常重启保存。
- “账号切换间隔”默认60秒，支持0—3600整数秒，明确输入0可关闭；清空、负数、小数、超范围均不能启动预检。确认摘要展示两项，修改后重新确认。
- 从上个实际SMTP结果处理完成起算，目标From与上次不同才检查切换间隔；它与目标账号自己的冷却取较晚截止时间，不能相加。首封没有切换等待，同身份只检查自身冷却，最后一批不追加等待。
- 每轮每账号最多一批；优先选择本轮同时满足两项限制的账号，没有已就绪账号才等待最早有效期限；不跨轮抢跑，不改变冻结的随机分配或转移收件人。
- SMTP失败或结果不明且允许继续时也更新完成身份与时间；零SMTP的本地失败不更新。切换记录仅在当前进程内跨取消及新任务共享，重启只恢复已持久化的同账号冷却池。
- 等待区统一显示“等待发送间隔”、待发账号和截止时间；每秒只更新本地展示，不发IPC或写数据库；取消和终态清除页面倒计时。

## 发件归属与数据库兼容

SQLite schema从4升级到5，在sent_history和mail_delivery各增加sender_address、sender_name两个非空TEXT列，默认空字符串。旧0/1/2/3/4库同事务升级，任意失败完整回滚；高于5拒绝打开。v4群目录和每群最新结果、模板、排除、设置和原历史继续保留。

宿主把实际SMTP发送器与已验证的From邮箱、当时账号名称绑定并冻结，投递开始前随整批预留持久保存。成功、进程中断后待核实、人工核实已发送均沿用该原始快照；账号后续修改或删除不改写历史。页面两种列表均展示名称及邮箱，支持按名称和邮箱搜索；字段缺失或空值显示“未记录”，不能用当前目录推断补录。旧人工新增、导入记录继续未知。

全账号仍共用全局sent_history、待核实和手动排除。已发送记录继续按收件人去重，同一收件人再次成功会更新最近账号；它不是每封邮件的独立审计流水。SMTP已接受也不代表进入收件箱。

升级前应正常退出旧版，备份整个%LOCALAPPDATA%/com.ahui.qq-group-exporter目录，包含可能存在的SQLite WAL与加密凭据文件。旧版不能读取schema5；回退须另存新库并恢复升级前完整备份，不能手动降低user_version。加密凭据仍绑定当前Windows用户。此次没有操作用户真实目录，迁移仅在临时合成SQLite上验证。

## 检查中修复的交互边界

- 清空切换间隔不再被Number空字符串转成0，避免误关闭限制。
- 非QQ邮箱历史的删除按钮及确认使用实际邮箱，避免目标显示为空；搜索变化撤销旧删除确认。
- 历史增加发件列后仍在卡片内横向滚动，窄窗显示滚动提示，滚动区可获键盘焦点；长名称、长邮箱允许换行。
- 冷却预登记返回后再次检查取消；投递事务取得SQLite写锁后及提交前再次检查取消。若取消，整批回滚，不发送SMTP、不生成待核实、不更新最近完成记录，清pending且不续期原登记期限。已经进入SMTP的当前批继续等待结果并按原规则记账。
- 手动排除读取挂起时合并新版本请求，离页或卸载使旧响应失效，补读完成前不解锁旧记录维护；输入、有效选择和重试保留。宿主持久返回旧版本时给出有限重试错误，不无限循环。

## 限制与回退

没有执行真实QQ登录、成员接口或SMTP投递，没有启动新原生EXE作端到端发信验证。界面使用隔离合成IPC；Rust测试验证真实本机事务和调度逻辑，不能代替邮箱服务的额度、反垃圾判断、实际投递和退信核对。900秒和60秒均为程序默认设置，不是服务商允许速率的承诺。

本轮源码备份位于artifacts/account-switch-baseline，依其manifest及生成patch可审计回退；未重置、覆盖用户其它工作，也未停止运行中的旧EXE。配置可填0关闭切换等待，数据库回退则必须恢复升级前完整备份。
