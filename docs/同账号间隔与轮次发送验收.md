# 同账号间隔与轮次发送验收

作者：ahui

日期：2026-11-09

本文保留上一发布包的轮首统一等待行为及验证证据。后续已补齐跨任务独立账号冷却、默认 900 秒和优先发送已就绪账号，当前行为见[账号冷却池与默认900秒验收](账号冷却池与默认900秒验收.md)。

## 问题依据与行为

用户实际操作时，多个账号各自只需发送一批，界面仍在第一账号结束后等待 300 秒。源码确认了两层原因：`assigned_mail_batches` 按账号连续排完全部批次；任务循环在任意两批之间一律等待完整间隔，错误地把不同账号也纳入统一等待。

按用户“只有同一个账号受限制，每一轮之后才等待”的要求，保留预检冻结的账号顺序和每账号收件人分配，改为每轮每个仍有任务的账号各发送一批。轮内串行执行 SMTP，切换账号不加间隔；下一轮开始前，等待该轮参与账号均达到各自的冷却期限，再整轮发送，轮内不再等待。

“同账号间隔”从该账号上一批结果处理完成起算，默认仍 300 秒、范围仍 1—3600 整数秒。后台给每账号记录单调时钟截止时间，轮首只取本轮仍有批次账号的最晚截止时间，减去已经消耗的时间；若均已就绪则直接开始。已发完的账号不参与后续轮次等待，最后一轮后没有倒计时。这个轮首统一等待是用户所要求的按轮执行：先就绪的账号等同轮其他参与账号就绪，一轮内连续发送各账号的批次。

| 场景 | 执行节奏 |
| --- | --- |
| 只有账号 A，多批 | A1 → 等待 A 间隔 → A2 → 等待 → A3。 |
| A/B 各有多批 | A1 → B1 → 等到下一轮参与账号均就绪 → A2 → B2。A1/B1 和 A2/B2 之间不额外等待。 |
| 5 账号、每账号只有一批 | 各账号依次发完，结束，不插入 5 分钟等待。 |
| 末轮只剩 A | 只核对 A 的冷却；其他账号发送耗时已经计入，不被耗尽账号的较晚期限拖延。 |
| 失败继续/停止/取消 | 继续只发送后续未尝试批次，不重试或换号；失败批次同样占用该账号冷却。默认失败停止或取消均不发后续批次。 |

随机均分、先全局过滤、每地址只分配一次、固定预检计划、账号凭据独立校验及共享已发送/待核实/排除不变。停止可立即结束轮间等待；当前 SMTP 交互仍完成结果处理，避免已接受却误认未投递。不会自动重试失败账号、重新平均分配、绕过未决投递或提升账号额度。

没有新增 IPC 字段。`intervalSeconds` 参数格式、默认值和校验范围保持兼容，语义变为同账号冷却。`nextBatchAt` 字段名仍保留，表示下一轮整体可开始的 UTC Unix 毫秒；只用于展示，真实等待使用 Tokio 单调时钟。`phase`、`stateRevision` 及读取/事件顺序保护沿用，倒计时归零不能自行触发发信或宣称该轮已开始。日志沿用 `job_id`/`batch_index`，补充固定账号序号、轮次和 interval_scope/wait_scope，不写账号凭据或收件内容。

数据库 schema 仍为 4，公开账号目录与密文格式、应用标识和数据目录均未改变，无本轮数据库迁移。退出程序后可换回此前多账号 EXE，恢复此前统一等待行为；不要同时运行两个版本。需要备份时完整保留应用数据目录及凭据子目录。跨更早 schema 版本的回退仍须按原迁移说明恢复完整备份。程序不会读取或改造真实用户数据库来完成本轮测试。

代码注释、README、说明、方案与验收记录同步。UTF-8 无 BOM 和原换行约定保持，方案文件原 CRLF、其余本轮源文件 LF。项目为 Rust/TypeScript，已读取 Java 手册的通用编码、校验、异常与注释要求；Java 语言和框架专属条款不适用。新增文档作者为 ahui；保留已有文件作者。没有改动依赖、锁文件、构建脚本、模板/群数据/登录模块或图标资产。
