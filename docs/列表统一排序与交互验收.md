## 现状、目标与验收范围

原群目录沿用 QQ 返回顺序，成员沿用获取顺序；发送记录使用数据库的 ID 倒序，其他目录沿用各自返回顺序，查找同类数据时缺少一致规则。本次按用户要求统一默认显示排序，并检查搜索、分页、刷新、勾选及相邻维护操作。界面仅在 1920×1080 验收。

默认顺序为 ASCII 数字 → ASCII 英文 A–Z（忽略大小写）→ 其他 Unicode 码点。相同前缀继续比较后续字符；连续数字按数值比较，例如 `2群 → 10群`、`a2 → a10`。数字比较不转浮点数，支持长号码及前导零；全角数字归入其他字符，不使用中文拼音排序。比较忽略首尾空白，空字段置后；空群名使用群号定位。同名项按稳定 ID 排列，避免刷新后位置跳动。

群聊、排除群按群名；成员、已过滤成员、本封群收件人按 QQ 号；模板库、导入预览按模板名；发送记录和手动排除优先按 QQ 号，否则按邮箱；待核实按完整收件邮箱。发件账号保留已有手动上下移顺序，运行日志与恢复审计保留业务时间顺序。

额外修复的根因：此前只在渲染时用 `min(page, pages)` 显示有效页码，状态仍保存失效的旧末页；删除后新增记录会重新显示旧页。本次在页数缩减时同步页码，搜索与跨页勾选仍独立保留。群头像此前使用 UTF-16 的 `slice(0, 1)`，会截断表情或扩展汉字，本次取完整码点。

排序只创建展示数组，不修改对象、原始快照或导出数据，也不改变已冻结的随机均分、输入地址、收件范围、实际队列、共享历史/排除规则、900 秒同账号冷却和 60 秒切换默认值。后端接口、配置及 SQLite schema 5 不变，无数据迁移。历史仍沿用原读取范围，列表排序不会改变全库发送状态检查。

各组件按源集合引用缓存排序，输入、勾选、计时更新可复用；单次为 O(n log n) 次比较和 O(n) 额外引用/字段，字符串比较另计长度。在当前 Node 24.18.0 环境对倒序的 10,000 条合成数字字段进行一次检查，排序为 3.383 ms，首尾正确且源数组未变；该值仅描述这一数据形态与机器，不是任意数据的性能承诺。

新增和修改注释与业务行为同步，新文件作者为 ahui。项目使用 Rust、React 和 TypeScript，按现有格式和适用的通用手册规则实现；Java 语法/Javadoc、MyBatis 和 PostgreSQL 专属条款不适用。本次未修改 Rust 业务、数据库或依赖锁文件。
